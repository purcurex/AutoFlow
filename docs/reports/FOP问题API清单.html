核查口径

本清单仅列测试环境实际返回的 FOP 接口错误及数据完整性问题。依据 2026-11-25 查询证据、最新版接口资料及金蝶官方 AIOpenAPI 错误码说明整理。FOP 基于苍穹开发，使用匹配当前网关的 AIOpenAPI 码表，不套用其他产品的同名错误码。未执行真实业务审核写操作。

即时库存查询
POST /kapi/v2/hzkj/ocbsoc/customer-stock/query
无法返回库存结果。		HTTP 200，业务失败；errorCode=DubboServiceLookup。消息明确提示 CustomerStockQueryService$Page must implement java.io.Serializable。响应数据在服务间传输时序列化失败。该文字码不是官方数值网关码；本次堆栈指向 Page DTO，不能仅因名称含 Lookup 就归因于服务未注册。修复 Page 及其嵌套明细对象的序列化；统一部署调用链各节点的 DTO 版本。复验空结果、有数据、下一页游标三种响应。另：当前契约仅返回客户／仓库名称，缺少公司、客户及仓库 ID；需要补充稳定标识及范围契约，才能验证受限账号库存隔离。
采购退货查询
POST /kapi/v2/hzkj/hzkj_einkauf/hzkj_purorderbill/queryPurchaseReturn
该接口所承载的数据不可查询；与采购入库／退料的 queryInbound 分开处理。		HTTP 404；errorCode=2530，路由未找到[网关]。官方解释包括请求路径错误或第三方应用未授权。当前请求路径与 v2_2 资料一致，需核查部署环境的路由发布、应用授权及资料一致性；仅凭 2530 不能确定是哪一项。确认该 API 是否仍保留；若保留，发布对应路由并为当前集成应用授权；若合并或停用，提供替代接口和字段范围。以同一应用身份复验分页查询。
采购退款申请查询
POST /kapi/v2/hzkj/hzkj_einkauf/hzkj_purrefundapplybill/queryPurchaseRefundApplication
无法查询采购退款申请数据。		HTTP 404；errorCode=2530，路由未找到[网关]。请求路径与 v2_2 资料一致；可能为当前环境未发布、应用未授权或资料未同步。尚无证据将其归为某一个确定原因。核对 API 管理中的路径、启用状态、部署版本及第三方应用授权。若不再提供，更新统一接口资料，明确替代接口；复验公司过滤和分页。
备货订单关联查询
POST /kapi/v2/hzkj/hzkj_ordercenter/openapi/bill-relations/stock/query
耗用关系不能完整追溯。		接口业务成功，但 complete=false；issues[].code=USAGE_RECORD_INVALID，提示部分耗用记录数量、SKU 或状态不完整。这是自定义业务完整性码，不是网关失败。样本 IO20261112000002 返回 8 个单据、8 条关联、1 条耗用记录；并不代表耗用链完整。检查源端耗用记录及接口映射，补齐数量、SKU、状态；issues 建议返回问题记录 ID／分录 ID 和缺失字段，当前 entry 为空。修复后重查样本，确认问题记录可定位、耗用关系完整。BILL 级数量标识 NOT_REQUESTED 本身不列为错误。

官方依据与错误码使用

官方将 2530 定义为路由未找到，其可能原因同时涉及路径与授权；2505 才是明确的应用未订阅该 API。HTTP 200 也可能承载业务失败，应同时读取 status、errorCode、message；关系查询还须读取 complete 与 issues。

金蝶官方：AIOpenAPI 错误码说明。DubboServiceLookup、USAGE_RECORD_INVALID 按本次响应消息分析，不虚构官方数值码映射。修复后使用当前集成应用及同样请求复验，保留实际返回作为关闭依据。
