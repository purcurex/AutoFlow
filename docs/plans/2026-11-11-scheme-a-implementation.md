# 方案 A 首轮落地计划

> 执行方式：在当前开发分支直接实施，保留既有未提交改动；使用 executing-plans、test-driven-development 和 verification-before-completion。独立文件范围采用 parallel-agents 协作，不提交或推送。

**目标：** 建立可迁移、可恢复的本地数据结构，接通本地读取与显式同步契约，完成五工作台前端切换。

**架构：** 来源事实、商品分录、关系与查询投影分层保存；页面请求查询本地数据库并应用当前本地权限。同步任务持久化，可靠变更目录、源版本及提交屏障是发布前置条件；审核继续使用 FOP 实时版本和幂等契约。

**技术：** PostgreSQL 16、TypeORM 版本化迁移、NestJS、Vue 3、Vitest/Jest。

**依据：** `docs/designs/workbench-database/schema-design.json` V1.2、`docs/solutions/HyperZoneFOP数据同步与查询方案.html` V2.1、`agent.md`。

## 全局约束

- FOP 访问暂停继续生效，不访问 Token、真实业务接口或启用真实后台同步。
- 不根据 SKU 补造来源关系；未知状态、缺币种、缺关联保留未知，不返回伪造的完整合计。
- 当前本地角色、组织、人员映射、公司和独立资源授权先于分页、计数与导出；不固化用户可见投影。
- 全部业务时间遵守项目最新确认口径；相对范围按本单收款日期，源单 C 端时间独立。
- 不重写旧迁移，不覆盖私有凭据，不将 Mock 作为 FOP 失败兜底。

## 核查重点

1. 未初始化、未接入与真实空清单必须区分。
2. 过期授权、组织调动、停用与个人/部门偏好变化不能复用旧结果。
3. 删除、关联解除和移出清单与新增修改同样必须同步。
4. 事件重复、乱序、失败重试、版本回退不得推进已应用水位。
5. 查询完成时间与源端同步截至时间分别展示；打开页面不触发源端同步。

## 实施结果与保留事项

　　61张工作台表已落地，43条迁移已执行；标准备份恢复、数据库约束及发布事务验证通过。当前本机默认使用local读取，可靠变更源未配置、FOP访问仍暂停，业务镜像0单。初始化与真实变更源对接尚未完成，不能据此认定五工作台真实业务数据已经上线。

　　采购分组独立付款/平台状态、复杂采购退货数量分摊、库存/客户选项、导出交付及供应商联系人操作仍有明确缺口，详见首轮实施报告；本轮采用明确待配置错误，不回退旧穿透API。

**实现裁定**

- 数据集单调发布版本保存在`datasets.applied_watermarks._local.projectionRevision`；保留命名空间与FOP源游标分开，删除全部订单也不回退。
- 来源事实、重建投影、清单移出与连续应用游标按完整提交组同事务发布；缺旧/新受影响订单或依赖版本不符时回滚。
- 身份冲突通过SQL冲突更新条件防御并发首次插入；不能仅依赖查重或`SELECT FOR UPDATE`。
- 当前FOP暂停及未发布可靠变更源属于真实数据验收前置条件；生产初始化、实时审核写入均未执行。
- 当前分支含历史未提交改动，保留原工作目录且未提交/推送，避免混入其他事项。
