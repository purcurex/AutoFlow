# Dashboard 待办看板实现

## 口径

五块卡片统计当前登录账号有权查看的履约订单，不受注册日期和回款年份影响。待审核、待履约、待出库分别对应工作台同名清单；待采购包含待采购和已采购待发货；待配货包含未齐套和已齐套未审核。组合卡片展示两个清单的笔数及入口，按互斥阶段计数，不能把五块卡片相加当作订单总量。

权限沿用 FOP 授权与当前本地成员范围交集。无岗位权限、未接入和查询失败分别表达，不能显示为真实零笔。权限或成员范围中途变化则拒绝整个响应。某个队列未接入不清空已经成功的队列。

## 实施步骤

1. 后端提取五卡定义和统计组装器，复用清单 matcher 与分页汇总；补充角色、零值、组合卡片缺项、范围变化及单项失败测试。
2. Dashboard 返回 queueStates 和 queueBreakdown，待办任务复用卡片数。移除真实模式必须拥有销售岗位的错误限制，保留分析图表独立权限。
3. 前端区分无权限／未接入／加载失败，禁用不可用入口；组合卡片提供两个清单入口，修正待履约文案。
4. 运行前后端测试、类型构建和静态检查，记录实际限制。
