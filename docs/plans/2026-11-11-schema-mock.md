# 方案 A 数据库模拟测试实施计划

**Goal:** 使用独立模拟数据库测试五工作台，沿用正式表结构、当前本地权限及查询接口；暂停真实 FOP 联调。

**Architecture:** 复制本地账号与组织到独立的 autoflow_workbench_mock 数据库，按既有 hz_fop_ 来源事实、完整分录、关系及查询投影创建可重置模拟数据。原业务镜像保留。即时库存／备货查询与审核通过独立即时能力入口，测试使用明确标记的模拟实现，正式环境再接 FOP。

**Tech Stack:** 现有 NestJS、PostgreSQL 16、TypeORM、Vue。

**Spec:** 用户本轮要求及 agent.md；当前表设计 V1.2、同步方案 V2.1。

## Global Constraints

- 不访问真实 FOP，不关闭暂停配置；模拟模式禁止生产环境及原业务库。
- 不新增本地库存管理、预占、扣减、采购或出入库执行业务。
- 模拟来源使用专用连接、公司及员工映射，不改真实绑定；离职 Ruth 不生成。
- 页面、合计、SKU 整单搜索、权限、分页、导出使用同一数据库模型。
- 库存／备货即时 API 与业务同步副本分开；审核模拟须校验版本、权限、幂等，结果反映到清单。

## Review Focus

- 模拟开关误用于生产／真实数据库时应拒绝启动。
- 多用户并行查询不能因模拟授权时间刷新相互冲突。
- 单 SKU 搜索保留订单全部商品，个人与部门权限在分页前生效。
- 审核重复提交及版本冲突不能重复修改或错误成功。
- 即时库存查询不写库存余额表，不误用周期同步数据保证实时性。
