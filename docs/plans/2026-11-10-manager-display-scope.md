# 部门经理全局展示范围与工作台计数复用

**目标：** 经理自行保存 department/self 展示偏好；首页、工作台、统计及导出沿用同一有效范围，不变更账号角色与权限上限。

**已确认方案：** 工作台返回的 total 是计数来源，不使用当前页 items.length。缓存缺失时调用同一个列表接口补齐；Dashboard 图表请求明确关闭后端待办统计。

**实施：** 使用现有 NestJS/TypeORM、Vue/Pinia；在当前工作区增量修改，保留其他未提交工作。

- [x] 用户字段 dataDisplayScope 默认 self、数据库约束和迁移；个人资料仅经理可修改该偏好。
- [x] 独立 effectiveBusinessScope 收窄经理至本人，保留 businessScope 授权语义；本地成员、图表策略与并发复验一致。
- [x] 全局页头切换，保存成功后清理会话业务状态并重载视图；跨标签同步，旧请求丢弃。
- [x] 缓存仅接收无业务筛选的工作台 total，按会话隔离；TTL、刷新失效、重复请求合并及错误状态隔离；组合卡片必须子队列全部有效才求和。
- [x] Dashboard 关闭后端队列查询，前端复用缓存或同一列表接口；待办独立于图表加载。
- [x] 验证本人/部门、未绑定、非经理、权限撤销、分页、筛选污染、旧响应、组合队列、图表失败和迁移。

**边界：** 个人偏好不赋予原本没有的图表/岗位权限。仅部门汇总型图表在个人模式隐藏；记录型统计只含本人。真实 FOP 尚未发布的队列仍明确未接入，不补造数据。不修改 dtr5b。


## 实现入口

- 数据库迁移：`backend/src/database/migrations/1794300000000-AddDataDisplayScope.ts`；字段非空，默认 self，仅允许 department/self。`PUT /users/profile` 接收 `dataDisplayScope`，经理身份与启用状态在 SQL 更新时复验，避免并发撤权。
- 数据范围：`effectiveBusinessScope` 只影响数据读写范围，不改变 `businessScope` 的账号角色和管理授权。个人 FOP 查询取已验证本人 masterId；记录型统计仅本人，独立部门汇总隐藏。本地客户、报价、沟通读取也收窄到本人。
- 页头：`DataDisplayScopeSwitch.vue`；保存成功后重建页面、清除业务缓存，跨标签同账号范围变化触发同样失效。保存失败保留原范围并提示。
- 计数：`workbench-counts.ts` + `workbench-dashboard.ts`；无额外业务筛选的任意页 total 可以入缓存，60 秒过期。手动刷新、范围/账号变化、FOP 操作使缓存失效；新请求覆盖旧请求，失败刷新不恢复旧计数。
- 图表：`getFopDashboard` 向后端传 includeQueues=false，并独立发布已完成的列表计数。图表 503 不吞掉卡片，权限或范围失效丢弃整份响应。组合采购/配货只在所有子队列 ready 后求和。
