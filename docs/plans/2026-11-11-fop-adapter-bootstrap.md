# FOP 新适配器与初始化实施计划

> 执行依据：用户要求直接执行现有新方案。主链按 executing-plans 实施；实时能力与来源规范化为独立并行任务。

**Goal:** 完成本项目新 API 适配、可恢复初始化与校验发布能力，清单无历史穿透，字段表与 FOP 改造清单同步。

**Architecture:** 保留共享本地副本查询、独立当前授权、服务身份快照与变更流。远端仅提供业务契约，本项目负责稳定 ID、归一化、投影、落库和原子激活。审核和两种库存使用独立实时接口。

**Tech Stack:** NestJS / TypeScript / PostgreSQL / Jest / Python HTML 生成器。

**Spec:** `docs/integrations/source/sync-query-solution.body.html`（V2.3）及 `agent.md` 最新业务更正。

## 约束与决定

- 保留已有工作区改动，本轮不提交整包历史改动；继续使用当前 checkout。
- 不修改 dtr5b 生产源码，不访问 FOP；保持 FOP_QUERIES_PAUSED。使用本地隔离库和注入式 HTTP Mock 验证。
- 现有 pageNo、afterOrderId 不冒充快照/变更流；尚未发布的扩展契约明确标记待提供。
- 源版本与大整数 ID 使用字符串，分录、删除和关联变化必须完整；失败不切换 active dataset。
- 文档遵循全局正文缩进与 HyperZone HTML 标准。

## Review Focus

- 初始化中断、重试、重复页和快照过期：保留游标、拒绝不同批次混入、旧数据集继续可用。
- 跨公司/连接/数据集错配：写入与权限均拒绝，不能以外部传入本地表名或 UUID 写库。
- 缺失必要业务事实、源数量与金额差异：阻止激活，不用零补齐。
- 审核不确定结果：不盲重试；实时权限和本地目录变更需复验。
- 删除发运单、解除关联、缺库存授权：不回退旧号码或历史清单。
