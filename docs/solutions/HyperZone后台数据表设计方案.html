01 · 设计总纲

来源事实按 FOP 单据保存，查询模型按本项目需求设计。核心业务单据独立保存，仅保留必要字段、完整商品分录、源端 ID 和可靠版本；不照搬 FOP 全部物理表及字段。

本设计承接已采纳的方案 A，采用来源事实、跨单关系、工作台查询投影分层，覆盖销售、发运、采购、配货、仓库的待办与完成记录，以及必要的备货、RMA、采购退货、库存、催办资料、审核和导出。FOP 继续承载业务执行，本项目保存可重建的查询副本。

字段级最终设计 V1.2，尚未执行建表。表名、字段、主键、外键、索引、选项、默认值和来源依据均列明；FOP 缺口仍按第 11 章跟进。本地实例、DDL权限、29张业务表及41条历史迁移已核验；已发现的恢复函数前置修复在独立验证库通过，原库尚未应用。

1.1 分层要求核查

设计要求最终设计落点核查结论
核心业务单据独立保存15 张独立单据类型表；source_documents 提供公共 ID／版本登记，source_lines 按来源单据保存完整分录。公共登记和分录不替代类型表。已体现。每类单据独立保留业务事实；不将采购、配货、售后压入订单 JSON。
仅保留本项目必要字段字段字典作为同步白名单；保留整单全部有效商品行及必要属性。payload／attributes 只保留白名单内未规范化的必要证据。已补强。完整分录指完整行集合，不要求复制 FOP 全部物理列；新增字段需说明用途和来源。
真实关联尽量到分录document_relations 保存两端单据／分录、relation_grain、源关系 ID、数量和金额分摊，并用复合 FK 约束分录所属单据。已体现并补充分粒度。SKU 只用于搜索；单据级关系不能推成商品级覆盖，缺少源行／分摊由 FOP 补齐。
五工作台复用基础和阶段workbench_orders、workbench_order_lines、14 个共享阶段字段及 memberships；分类以同一 rule_version 发布。已补强阶段固定列。异常、RMA 与正常队列可并存；不分别保存五份订单或一套互斥总状态。
本地账号组织与动态权限复用 users、organization_nodes、organization_employees；employee_bindings 只做人员映射，resource_grants 限定集成资源边界。已体现。查询、合计、分页及导出按当前本地范围执行；投影中没有按用户固化的可见结果。
核心问题数据库落点验收要求
数据时效持久增量流、事件收件、共享任务、用户刷新目标、投影依赖和发布时间；查询与同步进程隔离。区分源提交、发布、接收、应用、投影及页面可见时间；按北京时间08:30、09:00—18:30每30分钟、其余每2小时及手工增量追赶执行；以计划时点和实际追赶时长验收。
数据一致性可靠源版本、同代次复合外键、头／完整分录事务更新、幂等、关系分摊和投影原子发布。旧版本不覆盖新版本；无父子重复计数、跨公司串单、半套商品或不完整完成判断；列表、合计、导出一致。
FOP 可靠采集事件唯一键、连续接收／应用水位、提交组、删除标记、恢复代次及核对问题。FOP 人工与自动写入都留可靠记录；缺少版本、删除或稳定游标时，不将现有查询 API 冒充可靠增量。

数据库按同一公司、同一数据集保存一份事实，不按业务员或五个工作台重复建订单副本。来源字段只同步已确认必要范围；本地角色、组织、账号及既有客户开发、报价、选品、工作流和数据分析模块保持现有边界。

1.2 即时查询边界

本项目只承载数据展示与分析，FOP 负责库存及业务执行。待办、完成记录及备货订单使用本地共享查询模型；即时库存、客户备货库存及审核使用即时 API。库存相关预留表仅用于可选的短期查询缓存或历史分析快照，不是库存账本，不作为可用库存、预占或审核决策依据；当前模拟库不写库存余额表。

开发测试采用独立 autoflow_workbench_mock 数据库，复用本设计的字段、完整商品分录和分录来源关系，不创建另一套前端专用数据结构。模拟连接、员工映射及业务记录与真实本地副本隔离；真实数据接入后替换来源适配层，页面查询契约保持一致。

2.1 已发现的差异与处理

差异设计采用口径
前端仍有单一 allocationDocument；FOP 建单代码按订单包裹处理。订单到配货单为一对多，新增包裹和归包关系；完成判断核对全部有效应履约包裹。
手册仍出现部分出库、旧异常名称、发运必须履约已审核等历史文字。工作台整单出库；异常名称采用采购退货／订单取消／配货超时／物流异常／妥投异常；待履约沿用当前代码的已付且待同步规则。原始源状态保留。
旧手册／方案按关联收款时间或阶段完成时间筛选。客户付款筛选取本单 hzkj_receipt_date；源单 C 端时间 hzkj_datetimefield 和阶段完成时间另存；备货默认创建时间排序。
原生订单接口将 hzkj_order_amount 描述为订单金额；源码还存在 hzkj_total_amount。分别保存产品额、总额、运费、税费、优惠；金额字段绑定及结算币种不足时标缺口，不交换语义。
RMA 文档状态枚举、响应币种与已核对实现存在差异。按现行映射保存原值与规范值；退款币种当前缺失保持 NULL，不从本位币或原单补齐。
订货客户、付款客户、收货客户均存在。分别保存 hzkj_customer、hzkj_payingcustomer、hzkj_reccustomer；禁止用收货客户充当付款客户。
收件州省 hzkj_state 有元数据，当前详情响应未提供。字段可空，明确列为 API 缺口；不以其他行政区字段替代。
采购退货方案包含仅退款及多来源逆向；当前工作台仅展示实物退回。事实层保留完整种类及资金／实物独立进度，队列只按当前批准口径展示。未发布流程不在本地模拟执行。

历史手册与原方案不在本轮批量重写范围；上述差异必须在接入验收和后续手册更新中闭环，不能为了沿用旧文字约束错误的表结构。

source_documents 和 source_lines 提供通用身份及外键落点；15 类核心单据各有独立类型头表，领域分录扩展按所属单据保存必要业务字段。每条分录均保留真实源行 ID 及版本，公共行表按单据严格隔离；完整商品分录包含该单全部有效商品行及 BOM 父子，不受 SKU 搜索或用户筛选截断。查询投影按本项目页面、筛选、阶段、合计和导出需求设计，可由来源事实重建。

履约 → 包裹 → 配货／发运一笔履约有多商品、多包裹、多张有效关联单；以真实包裹及来源分录计算齐套和完成。
履约／备货 ↔ 采购一单多采购、多单合并采购；关系数量和金额分摊只取实际来源，不按相同 SKU 猜配。
RMA → 原履约 → 采购退货客户售后与供应商追偿分别关联；多笔退款保留独立单据和币种，结束状态不覆盖历史。
公司 → 当前数据集新快照先导入、追平及核对；通过 active_dataset_id 原子切换，旧数据集保留恢复与审计引用。

例如采购单 P1 合并履约 A、B 的商品，P2 另关联 A：P1 变化只重算 A、B；P2 变化只重算 A。按采购单分组时先限制有权业务来源，再对分摊量合计，不能把整张采购单总数量重复归给每笔履约。

同一关系的上下游单据、分录及包裹必须在同公司、同数据集。异步乱序导致端点未到齐时先保留收件／待补证据，端点及来源量核实后解析；暂态不能发布“采购已完成”或“全部已出库”。

05 · 字段与约束规范

规范明确要求
主键与环境本地主键 UUID，由应用生成；FOP 内码、工号、单号、1688 及 Shopify 编号使用字符串。connection_id 隔离测试／生产，company_id 隔离公司，dataset_id 隔离快照代次。
来源身份来源唯一键为 dataset_id＋entity_code＋source_id；typed header 固定实体编码 CHECK，并与登记表复合外键关联。源单号仅用于展示和核对。
版本与游标source_version 使用 numeric(30,0)，前提是 FOP 提供单调可比较版本；缺失保留 NULL／未验证。游标不透明，不做字典序比较；本地投影修订号及 payload hash 不能作为审核版本。
金额、数量与币种金额 numeric(28,8)，数量 numeric(24,8)，API 传十进制字符串；币种未知为 NULL。原生正负方向保留，源单总额、申请额、实收、实退及平台退款各自保存；精度及溢出在取样验收后确认。
时间事件与日期时间统一 timestamptz；无时区源时间按已确认 Asia/Shanghai 解释，前后端按 UTC+8 计算业务范围。customer_paid_at、consumer_paid_at、审核、采购付款及阶段完成不得混用。
未知值业务真假事实可空，未知不存 false；金额未知不存 0；原生状态保存 text／varchar，规范枚举使用 CHECK 或映射，不建立难演进的 PostgreSQL 原生枚举。
完整分录源行 ID 与父子关系稳定保存；seq、SKU 不能替代源行 ID。删除行保留失效标记，更新旧／新关系；展示商品与头、队列在同一投影事务发布。
字段白名单只同步字典明确用于展示、筛选、排序、阶段计算、关联、权限、核对及恢复的字段。常规字段使用规范列；payload／attributes 仅作受控补充证据，不保存完整 API 原文或未使用 FOP 字段。
FK 与范围复合外键同时覆盖 company_id、dataset_id 与目标 ID；同单父行另含 document_id。跨表类型、数量守恒及 RMA 冲突不能靠普通 CHECK 跨行查询，须事务内校验／受控约束触发器。
删除源事实使用 tombstone，不任意 CASCADE 删除业务证据；派生数据可重建。旧数据集、导出与回执关联未到保留期时不得清理。
机密与权限只存私有凭据引用，不存 Token／AppSecret；SQL 日志不输出整单隐私载荷。同步事实只由 Worker 写，页面不能直接操作数据库或伪造权限。

主键、外键和唯一约束按 PostgreSQL 约束语义执行；列表、合计及快照使用一致读取，避免默认逐语句快照造成混合结果。约束参考；事务隔离参考。本地已核验为 PostgreSQL 16.15，迁移仍不预设 pg_trgm、特殊 UUID 扩展或特定版本的 NULL 唯一语法已经可用。

07 · 查询与业务口径

查询先读取当前公司在线数据集及账号角色／组织，得到获权业务员和资源范围，再执行条件、合计、排序与分页。SKU 搜索用命中条件找订单，结果返回完整展示分录。采购组、RMA、采购退货均先限制来源订单，再聚合当前有权关联。

队列／能力事实与查询口径
待支付、待审核、销售完成待支付取明确未付；待审核取已付且待审。销售完成仅履约 billstatus=C，已支付、已发货、已取消不作为排除条件。

7.2 需求、采购分摊与包裹

一条订单商品的净采购需求只在 workbench_procurement_demands 保存一次。需求 10、两张采购单分别覆盖 6 和 4 时，需求表保存 10，workbench_purchase_allocations 的两条分摊保存 6、4；采购单行又合并多个客户订单时，发货、入库、取消、退回及金额仍按真实来源分摊，不能复制整行数量或自行按比例摊派。

申请退款、RMA 建单、已退款及实物退回均不直接扣减履约需求。明确生效的订单变更／取消调整需求；供应商确认取消调整原采购覆盖；退回后是否补采取 FOP 的剩余供货义务。库存覆盖、取消效果或分摊不清时保留 unknown，不能通过截为零掩盖超额分配。

order_packages 保存 FOP 不可变包裹键，document_packages 明确关联配货、发运、通知及出库单，允许真实的多对多关系。package_lines 保存同订单商品的归包数量。现有显示包裹号可用于核对，不能单独作为稳定身份；缺少可靠键及关联时，整单完成口径保留待补。

08 · 同步与一致性

  1. 可靠采集：FOP 在实际提交路径留下版本、事件和删除；人工、API、插件、任务、回调均覆盖，事务回滚无有效事件。
  2. 接收与取数：一页事件和 received_cursor 同事务保存；事件按源 ID 去重，按单据合并回查更高完整版本。
  3. 应用事实：同单据版本受锁或条件更新保护，完整提交组内头、全部分录、旧／新关系和全部重算义务原子应用；无版本、乱序关系或币种缺口进入 issues。
  4. 发布投影：在同一事务替换展示头、展示行、分类结果、依赖及采购分摊，并满足对应事件义务；全组义务完成后推进连续 applied_cursor。
  5. 刷新与恢复：按各请求提交屏障确认采集覆盖、发布和应用；任务领取有代次，崩溃可重试，水位不能越过失败项。

8.1 初始化与在线切换

先创建 building 数据集并保留 C0 后续日志，全量写入该 dataset_id，回放增量至目标、核对 ID／版本／关系／金额后，将公司 active_dataset_id 和数据集 active 状态在事务内切换。在线查询继续读取上一完整数据集；首次没有在线数据集时返回未初始化。旧数据集按恢复、导出及审核引用的保留规则清理。

初始化的新旧代次使用不同本地 UUID，不能跨代次复用关系外键。源端身份始终由 connection／company／entity／source_id 复验；导出及未决审核跨切换时须按该稳定来源身份重新核权，不仅依赖旧本地 UUID。

8.2 查询快照与重算

列表、计数、合计优先在同一 SQL 完成，或采用 REPEATABLE READ READ ONLY 事务；默认 READ COMMITTED 的多条查询不保证同一快照。异步导出采用短 REPEATABLE READ 事务固化 export_items 后退出快照，再生成文件，避免长时间保持数据库事务。分页跨多个请求默认读取各自当前完整结果；需要固定大范围快照时使用导出任务，不声称附上 revision 就能冻结历史数据。

本地重算修订号在实际发布事务内更新，不能把提前领取的 sequence 最大值当已提交全局水位。源头与本地最终一致，关联缺口显式标识；审核及库存写入仍由 FOP 实时标准操作保证。可重建查询投影参考。

8.3 事件完成与崩溃恢复

替换来源关系前保存旧受影响订单，与新关系集合取并集，形成 sync_event_requirements。事实更新、旧／新关系、全部完成义务和任务唤醒同事务提交，崩溃后可按义务继续重算，不依赖已被覆盖的旧关系。任务可合并，各事件的目标版本向量仍独立保留；投影发布与义务满足同事务写入。

事件全部义务满足后才完成；事务组全部事件完成后才越过组边界。源订单删除也要保留 tombstone，完成原队列移出义务。API 缺口导致的未知分类需显式披露；影响清单全集的未知不能变成完整合计或伪零。

8.4 提交组与屏障契约

首版要求每公司一个有序业务提交流，同一源事务所有单据事件均在同流同组，返回完整成员清单、数量、摘要和结束边界。sync_commit_groups 核对完整性后才应用，不能跨流拆分一笔业务事务。库存及授权可独立成流，以各自版本和屏障证明覆盖，不宣称所有资源在同一瞬间原子一致。

sync_barriers 固化 C0、初始化切换目标及手工刷新目标；公司业务屏障落在完整提交组边界。初始全量需源一致快照，或可证明等效的版本化分页及回放协议。所有目标流采集、发布、连续应用与对应投影义务达到目标后才切换／报告刷新成功；普通可变分页或旧流头不足以证明。

8.5 北京时间同步计划

每日按 Asia/Shanghai（UTC+8）执行，与用户登录、页面活跃和部署服务器时区无关。“全量数据增量同步”指所有已授权公司及业务资源范围内的变更，不是每次重新拉取全部历史记录；不受当前清单、当前页、日期筛选及业务阶段限制。

09 · 权限与操作

管理员按现有 users.role=admin 获得本地全部业务范围，仍受集成公司及独立资源授权限制。业务员本人、经理个人／部门、协同岗位以及 HR／商品管理业务关闭规则继续复用现有服务；本轮不重建角色体系。部门层级通过当前本地组织计算，不将旧部门名称固化为授权依据。

统一集成读取身份只用于后台同步；审核先复验本地角色和当前来源归属，再向 FOP 实时预检，使用 FOP 可验证的预期版本及真实操作人条件提交。action_targets 的本地唯一键不能替代 FOP 端的原子幂等。unknown 结果按原请求核对，暂停本批尚未提交目标；不离线审核，不从本地副本直接改业务状态。

导出开始、快照及交付时重验权限；组织调整、停用、归属与资源撤权使旧选择失效时拒绝旧结果。收件信息、联系人及渠道执行各自资源规则；供应商催办打开前复验当前待发状态、采购来源和联系人版本。

9.1 撤权与归属时效

本地停用、角色、部门及查看模式在每次请求重新计算，立即影响新请求。FOP 集成资源撤权、订单业务员及客户归属变化必须进入可靠资源／业务事件，并更新来源版本、反向投影和授权范围版本。仅重新执行本地 SQL 不代表已获知 FOP 最新归属。

本设计提出普通读取最多 60 秒的授权与归属核验窗口；需同时证明源采集健康、相关变更已连续应用，或有未超过该窗口的实时核验。无法证明时阻断相关资源并提示同步／授权状态；不继续展示可能已撤权的数据。该时效作为上线验收条件，未获得 FOP 契约前不承诺已实现。

导出交付、审核及敏感联系人操作要求实时回源核验当前资源和来源归属，记录版本／范围凭据；批量核验接口缺失或调用失败时暂停交付／操作，不能用未过期的本地快照替代。普通列表仍从本地数据库查询，不按每位用户复制全量事实。

10 · 建表实施顺序

先评审本字段方案，再生成 TypeORM 实体、迁移和查询适配；本轮未生成可直接执行的迁移，不开启 synchronize。创建结构、写入测试事实、启用可靠同步、切换页面数据源及开放审核分别验收。

采购退货／供应商退款实体和规划存在，当前资料包未含完整业务查询链。明确退货申请、实物路线、1688 退款业务号、采购退款收款单及来源分摊；工作台仅展示实物退回。

12 · 验收与交付

验收场景应有结果
跨环境／公司／代次误关联复合 FK 或应用入口拒绝，不能跨测试／生产串单。
同单多字段、多行、BOM 父子变更可靠单据版本更新；展示整单一致，父子数量／金额不重复。
分录删除、来源解除、作废、反审核旧关系失效，旧订单及新订单均重算；不会单向只前进。
重复／乱序／晚提交／消费崩溃重放幂等、旧版不覆盖，失败不跳水位，租约过期旧实例不能提交。
初始化期间持续新增、变更、删除新数据集回放核对后原子切换，在线没有半套快照。
一单多采购、合并采购、部分采购退货按来源行及数量分摊；无权来源不进入采购组总量。
一单多包裹、多配货／发运单缺失包裹不被已有单据掩盖；全部有效范围才完成。
金额零值／空值、缺币种、退款与收款零与未知分开，精确小数和分币种合计；不同资金事件不重算为同一金额。
销售完成与异常、RMA 并存单据已审核仍在完成清单；异常及历史 RMA 不覆盖正常阶段。
账号降权、部门变化、经理个人模式下次请求按当前本地范围，旧缓存、导出及选择失效。
客户库存与公共库存、选单查库存客户当前归属、SKU、仓库及独立授权正确；不读取其他客户权益。
SKU 命中一品、多品整单导出页面及导出保留整单全部商品，同筛选和排序。
审核前后金额／商品／渠道并发变化旧版本提交被 FOP 拒绝；unknown 只查原请求，不重复审核。
北京时间调度／手工刷新、源采集落后校验08:30、09:00—18:30含端点及跨日2小时时点；手工含移出清单；健康无法证明不伪报刷新完成。
缺 API／订阅／版本／来源关系明确未接通或待补，不返回伪零、不回退 Mock。
创建／回滚／恢复演练临时库迁移通过，原有 29 张实体相关数据保留，新增副本可重建。
