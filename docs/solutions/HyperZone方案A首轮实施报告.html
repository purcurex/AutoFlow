01 · 实施结论

方案 A 首轮数据库与代码改造已落地。当前本机工作台默认查询本地数据库，刷新不再触发 FOP 穿透读取；进入／切换清单在本地首屏后按需申请增量；显式同步通过后台持久化任务追赶变更。

真实业务副本尚未初始化。61 张表已创建，来源业务单据为 0；FOP 访问暂停、自动同步关闭，可靠变更源适配器未配置。此状态不能认定为真实业务数据已接通或真实空清单。

1.1 本地模拟测试补充

当前页面已切换独立数据库 autoflow_workbench_mock，沿用已创建的61张工作台表及当前账号与组织，来源事实、商品分录、关联和查询投影均存入同一既定表结构。基础数据集含280笔履约订单、120笔备货订单，并关联采购、配货、发运、RMA与实物退货。原 autoflow_local_demo 保留真实副本状态；真实 FOP 访问暂停。

测试能力实现
工作台查询九类履约待办、五类完成清单、备货阶段、RMA、异常及实物采购退货；覆盖多商品、部门与个人范围、近期及历史记录。
采购视角多笔履约合并采购、同一履约关联多张采购、统一待创建组、供应商不同发货时效；商品来源按明确分录关联。
即时查询与审核模拟库存与备货即时响应，不写库存账；模拟审核校验版本、会话及请求幂等，并更新单据及清单归属。真实审核仍须接 FOP 即时能力。
导出与重置模拟库导出复用既有 Excel 模板，支持筛选全量和选中数据；npm run workbench:mock:seed 重置模拟业务数据，不重置账号与组织。

模拟数据用于前端功能验证，不代表真实 API 已接通。生产环境和原业务库禁止开启模拟写入；本项目定位为数据展示与分析，库存管理、预占和扣减仍由 FOP 承担。

1.2 按需同步改造

进入工作台或切换清单先显示本地数据，首次加载结束后申请增量；搜索、筛选、排序、分页及采购查看维度切换不触发源端调用。导航60秒节流，同一公司与数据集跨用户共享任务，每位用户有独立回执。

手工同步绕过导航冷却；已开始任务后到达的手工请求合并下一轮，不能用旧屏障冒充本次完成。Worker按数据集串行推进，任务完成更新全部关联回执。审核或导出进行时延后页面重查；自动导航同步在清单变化时废弃旧结果，手工同步跨清单保留进度，会话变化均取消观察。

新迁移1794402000000已应用于原库、独立Mock库和验证库；未变更原库业务数据。当前仍使用Mock，真实变更源未配置、FOP暂停、自动同步关闭。本轮通过合成变更源在独立验证库验证调度与追赶，不代表真实接口已经联通。

02 · 代码范围

模块本轮结果边界
数据库61 表、948 字段、252 外键；107 唯一索引、42 查询索引、110 CHECK。版本化迁移执行完毕；原账号与组织保留。
履约清单五工作台复用本地订单、完整商品与非互斥清单投影，支持 SQL 范围、筛选、合计和分页。未知分类明确不可用；不将 unknown 当作不存在。
备货与 RMA本地读取，SKU 命中仍展示整单；RMA 使用独立资源授权及明确来源关系。业务阶段依赖已核验的归一化事实。
采购分组本地需求与采购分摊查询；待建组置顶、整单商品和分页。采购整单付款、平台下单独立状态未能证明时显示未知，对应筛选阻断。
采购退货支持明确实物类型、单一来源退货分录关联的履约订单。复杂多来源退货分摊和物理进度缺口保留，不按 SKU 或比例补造。
权限与人员当前本地角色、组织及已核验员工映射决定范围；交付前重新读取当前权限。目录验证含人员 masterId 即可，无需本人 FOP 代理登录；裸 ID 仍不视作已核验员工身份。
同步持久化请求、幂等、租约栅栏、版本与身份校验、完整提交组发布、删除及移出清单、分页屏障追赶。真实源未配置；仅在独立库用受控事实验证。
前端五类页面共用查询/同步入口；查询时间与源端同步截至时间分开；同步成功后重查并清理旧选择和计数。导航按需触发，筛选／翻页只查本地；无页面定时、聚焦或联网轮询。Mock与暂停状态不触发源端同步。
导出、库存、供应商操作本地模式统一拦截不具备可靠证明的旧入口。导出交付需实时授权复核；库存、客户选项和联系人关联尚未接入。均不回退旧穿透查询。
审核保留已有 FOP 实时预检、版本及幂等操作路径。未执行真实写操作，未改为本地库直接审核。

04 · 同步与查询契约

浏览器继续调用本项目原 BFF 路径；local 模式由本地查询服务处理。同步使用集成身份和全授权公司变化，不把当前页面、业务筛选或用户可见结果传给源端充当同步范围。

接口 / 入口含义
GET /workbench/replica/status本地初始化、暂停、同步状态、数据集版本及已证明的源同步时间。
POST /workbench/replica/syncrequestKey 幂等；创建增量任务。未初始化或源未配置时明确返回原因。
GET /workbench/replica/sync/:id仅本人可观察任务；当前公司、组织及数据集范围变化后不交付旧结果。
ReplicaChangeSource内部可注入变更源端口：barrier + 有界分页 groups。目前默认 Unconfigured；不是已经发布的 FOP API。
ReplicaPublisher同事务发布事实、分录、受影响订单、清单移出及连续应用游标；失败回滚。

数据集发布版本使用 applied_watermarks._local.projectionRevision 保留命名空间，独立于 FOP 不透明游标；删除全部订单仍保持单调。重复 JSON 的对象键顺序变化不会产生虚假冲突，数组顺序保留。

兜底计划按北京时间每日执行：08:30 一次；09:00—18:30 含端点每 30 分钟；其余固定 20:30、22:30、00:30、02:30、04:30、06:30。重启后合并追赶最近遗漏计划，不逐次重放大量过期任务。当前暂停且未配置可靠源，定时器未启用，也不显示虚假的下次自动执行时间。

4.1 本轮同步策略

“同步数据”位于工作台切换栏右侧，五个工作台共用入口和状态；采用深浅主题一致的轻量样式，常态只显示最近同步时间，未知显示“—”。各清单标题区只保留本地“刷新”。手工同步覆盖全部已授权业务资源，与当前清单、搜索、筛选及分页无关；后台公司范围、合并和权限规则保持。

POST同步请求支持manual与navigation，浏览器不能发起scheduled触发。导航节流返回skipped而非成功；跨用户合并只共用源任务，各回执仍按当前账号验证。WORKBENCH_SYNC_ENABLED仅控制定时兜底，真实源Worker可单独处理已授权手工任务；Mock／暂停／未配置可靠源时均不运行。

业务部门筛选及分析维度统一限定为营销中心、业务一部、业务二部、业务三部、业务四部，选项按当前账号权限展示；仓库、信息管理及其他协同部门不作为业务归属部门。组织架构与岗位授权保持独立。

06 · 真实数据启用前置项

事项FOP / 集成侧要求
可靠变更采集所有影响已接入字段、分录、状态、关联、归属及删除的已提交变化都要覆盖，包括人工操作、API、后台插件和自动代码；提供源版本、操作、提交组成员与完整性证明、稳定游标及保留窗口。
版本快照和源屏障完整提交组必须能取得相应版本的必要事实与分录，或提供一致性快照令牌；不能用任意“当前查询结果”冒充某个历史提交版本。不直接用最大 ID 代表已提交水位。
初始数据提供一致性初始快照与起始/切换屏障；补齐本项目原始响应→必要事实/完整分录/明确关联→共享投影的生产映射及初始装载。完成校验后再原子切换活动数据集。
授权和归属快检提供公司、独立资源和当前归属的短期有效证明，独立于按需及低频业务增量。当前严格校验至多 60 秒，缺证明阻断；大规模部署前须实现覆盖水位证明，不能靠每分钟全表改写所有订单来维持新鲜时间。
采购与退货提供独立付款/平台状态、供应商实物进度和到分录的精确来源/退货数量分摊。不能由相同 SKU、退款状态或整张采购单平均分配推导。
独立能力库存、客户当前归属及联系人需相应资源证明和关联；导出交付须复核当前范围；审核须真实预检、源版本、幂等回执及未知结果恢复。
启用与验收先明确恢复 FOP 访问，再部署并注册可靠变更源适配器、初始化、影子核对与容量压测，最后启用计划同步。当前没有恢复访问或执行真实审核。

V1.2 表设计与建表前报告保留其历史核验状态。当前实施结果以本报告及 implementation-status.json 为准；后续补齐生产映射和接口后，再更新真实数据验收结果。
