采购退货业务方案

单笔业务发起 · 合并采购部分退货退款 · 已发货未入库处理 · RMA 售后衔接

2026-11-05 评审稿

采购退货单 → API推送1688 → 供应商处理 → 仓库实物退回（预约包裹快递） → 退款核对。以现有业务单据串联申请、实物与资金结果，工作台负责查询跟进，FOP 负责办理。

01 单据载体

统一名称为采购退货单，处理类型为仅退款、退货退款。优先扩展现有采购退料申请实体，不另建独立“退货事项单”；客户售后、采购退货、实物出库分别由各自业务单据承载。

业务单据核心职责
履约订单 / 全款备货单确定业务来源、客户、商品及本次可处理范围。
RMA 售后单确认客户退款、退货、补发方案；需要供应商追偿时关联采购退货。
采购订单提供真实采购明细、供应商、采购账号及 1688 主 / 子订单；承载“取消采购”操作、范围、原因及结果，关联后续采购退货单。
采购退货单承载申请、审核、1688 退款号、供应商处理、返运物流及结案结果。
采购入库单 / 退货出库单记录真实入库及退回。包裹预约、取件、面单与出库结果关联采购退货单。
收款单 · 采购退款类型承载供应商退款，根据 1688 接口核实的实际退款结果自动创建，关联采购退货单、采购单及退款业务号。
收款调整单承载客户退款，沿用 RMA 侧原链路，与供应商退款分别核对。

02 发起与取消

入口允许条件限制
履约订单来源正常有效且已审核、公司未实际出库；供应商缺货、错发、超时或质检问题，客户继续原履约；存在真实采购来源及剩余额度。同一需求未被 RMA 承接；客户提出退款、取消、退货或补发时，转 RMA。
RMA 售后单客户方案已审核确认、明确需要供应商追偿；无论公司是否出库，均从 RMA 关联发起。草稿、待审核、驳回状态不下推可执行采购退货单；仍须采购退货自身审核。
全款备货单来源有效，付款、采购分摊及客户权益已核实；可处理数量未被履约占用或使用。已占用先处理关联履约；已出库转原履约 / RMA 核实，不重复退同一来源。
采购 / 收货 / 入库快捷入口能定位具体履约或全款备货来源，按上述规则办理。只增加入口，不另开流程；已出库后的纯采购价差补偿由采购授权办理，不虚建客户 RMA。

“未出库”以公司仓库 / WMS 实际出库为准，供应商发货、发运单审核或 Shopify 同步均不能替代。未采购只调整需求；供应商交易未付款只按事实取消，不虚构退款。

RMA 客户侧已完成，采购追偿仍可继续；同一需求不因 RMA 结案改从履约单重建。RMA 撤回或作废后，先核对已发生的平台、实物及资金结果。来源已取消的历史遗漏，经授权补登原来源与审批，不丢失应追偿款项。

取消采购与退货统一处理

采购订单新增“取消采购”操作，表示终止指定采购义务；是否需要退款、实物退回，按真实付款与货物状态分流。未付款取消记录在原采购订单；涉及供应商退款或退回商品时，统一关联采购退货单，不新增取消采购单。

实际状态执行路径完成依据
确认未推 1688、未付款、未收货原采购订单登记并审核本地取消。核实无外部订单及后续执行后回写目标来源，不生成退款收款单。
已推 1688，未付款、未发货原采购订单登记待取消；核实平台处理结果。待人工确认1688接口逻辑。平台取消已核实后回写；结果不明保持待确认，不仅凭接口请求返回即标已取消。
已付款 / 部分付款，未发货关联采购退货单，按“仅退款”处理已付款部分，确认目标范围停止供货。采购义务解除、退款结果分别记录；退款成功后自动创建采购退款类型收款单。
供应商已发货，未入库关联采购退货单，按在途截回、拒收或到仓退回处理；退款方式按平台真实场景确认。实际返运 / 交接、供应商处理与退款核对，不按未付款取消直接关闭。
已采购入库需退实物时走退货退款及退货出库；保留商品的价差补偿走仅退款。实物与资金结果回写采购退货单；补偿不视为取消商品数量。

合并采购只处理选定业务来源。平台不支持部分取消时保持待确认，转人工协商；整单取消必须核对所有受影响来源并取得授权，不能为取消某履约单的 2 件而取消整批 100 件。采购取消不等于履约 / 备货订单取消；客户取消仍按 RMA 审批。

原采购单独立记录取消进度：待确认、处理中、已取消、取消失败，保留付款及历史金额。只有确认对应采购义务已解除后才回写可重采范围；客户继续履约则按批准范围重采，客户需求终止则关闭对应需求，不自动重新进入待采购。

执行前重查平台状态，同范围取消与推单 / 付款须受控；期间已付款或已发货时停止原取消路径，转关联采购退货办理。取消处理中、退款处理中及结果不明的范围不重复申请、不提前释放。

03 单据流转

采购审核确认来源、处理范围、证据与额度后，FOP 服务端推送 1688。供应商同意实物退回后，仓库关联退货出库单并预约包裹快递，寄出后回传真实物流；预约成功不等于已出库或已取件。

供应商退款自动建单

1688 接口核实退款成功 → 自动创建收款单（采购退款类型） → 财务核对 → 回写采购退货单。金额取平台实际退款，保留货款、运费及币种，不以申请金额代替；退款与实物退回独立跟踪。

规则处理
创建条件已核实采购账号、退款业务号、实际金额及来源关联；申请受理、退款处理中或结果不明时不创建。关键信息缺失先待核对，补齐后按原退款号补建。
一笔退款，一张收款单按租户 + 采购账号 + 退款业务号唯一建单；重复通知、查询及重试复用原单。不同退款业务号分别建单，关联明细保留来源分摊。
自动创建，按原流程核对收款类型固定为采购退款，自动建单后按既有流程审核 / 确认到账，不自动当作财务已核对。该类型不触发客户充值、钱包入账或客户回款统计。
失败与差异建单失败可按同一退款号补建，不重新申请退款；已审核收款单不被后续同步覆盖，差异按财务流程处理。

客户退款仍由收款调整单办理。采购退货单在采购退款收款单核对、所需实物义务完成后结案；供应商拒绝、退款差异或提交结果不明，保留原单跟进。线下采购核实真实退款凭证后，使用同类型收款单登记。

04 一单多品退货

一张履约订单、一单多品，可对应多张采购订单及多张采购退货单；同一 SKU 也可能分属不同采购订单。采购侧按实际采购明细拆单，在原履约订单 / 同一 RMA 下统一查看各单进度，不将整笔履约订单视为只有一个供应商或一张采购单。

采购订单视角多数为部分退货、部分退款。每张采购退货单只对应一笔业务来源，并关联一张采购单、一个供应商、采购账号及外部主订单；跨采购来源拆单，同一采购来源的多商品在平台允许时可归入一张退货单。

处理目的数量与金额口径
取消目标采购占用并核销本次取消数量；实物退回量可为 0，按实际交易申请退款。
退货退款记录申请 / 实际退回数量和申请 / 实际退款金额；在库商品冻结对应库存。
保留商品，仅退部分货款只占用可申请金额，不自动冻结库存、不减少商品或备货权益。
全款备货退回同时核验客户权益、实物及履约占用，按批准结果更新；不能退走其他订单已占用商品。

例如履约订单 A 包含 SKU-A 2 件、SKU-B 1 件，分别来自采购单 P1、P2、P3。本例全部商品需向供应商退采购：从 A 或其 RMA 统一确认范围后，关联生成 T1、T2、T3，各单可按不同付款、货物状态分别办理。

各采购单若还合并其他履约订单，本次只处理 A 对应的商品、数量及金额；未涉及的商品继续原流程。各退货单分别核对退款和实物结果，一张完成不代表其余完成；采购退货汇总保留未结、异常及关闭结果，客户 RMA 仍按客户侧规则结案。全款备货沿用同样的多采购来源拆分规则。

同一履约订单可关联多张采购退款收款单，按实际退款业务号去重、分币种汇总。来源数量、折扣与运费按真实采购分摊计算，申请金额、平台退款及财务确认金额分开记录，不用客户销售金额代替。

申请不得超过来源剩余数量 / 金额及平台允许范围，历史已完成和处理中申请均计入核验。同 SKU 的 1688 子订单不支持本次部分范围时转采购协商，不扩大为其他客户的整批退款退货。

05 未入库处理

区分供应商发货、物流签收、采购入库与 1688 确认收货。未入库退回，以采购退货单关联原采购 / 收货单据，记录处理数量、交接与返运物流；已入库退回，以退货出库单执行。

FOP / WMS 未具备完整的到货拒收退回能力时，实物到仓后先真实隔离入库，再退货出库；隔离商品不可配货。合并包裹无法分离目标商品时，不默认截回整包，其余来源继续正常收货。

06 关联与防重

防重依托来源单据、RMA 与采购退货单的关联及明细额度，不新增独立事项单。所有入口调用同一服务，按原业务来源、采购分摊和本次处理范围查重；RMA 号不作为重新建单的依据。

情况处理规则
已有同范围采购退货单草稿继续编辑，待审核查看进度，处理中继续跟进；不重复下推。无查看权限只提示联系负责采购。
履约先发起，后建立同需求 RMARMA 关联原采购退货单，保留原来源、审批与执行记录，不另建一单。
取消采购转退款 / 退货复用或关联同范围采购退货单，保留原取消操作关系。取消与退货共用来源数量 / 金额核验，同一数量只结转一次，不因两边回写重复释放。
新增或差额需求核对已处理 / 占用范围，按剩余额度重新审批；平台已处理中不改原申请，追加部分关联办理。
并发、重复点击及平台手工申请服务端串行核验关联来源，审核原子占用数量 / 金额；所有入口及备货转用共用额度，按平台退款号去重。
超时、撤回及关闭平台结果未确认不重推、不释放额度；只有核实未执行或已有效取消后才释放对应部分，已退款 / 已寄回不能通过删单恢复。

单据状态变化不自动改变原订单进度。需要取消、拦截、关闭采购需求或扣减库存时，执行对应业务单据操作；同一 RMA 的追偿审批不能通过改入口或关闭单据绕过。

07 落地重点

范围核心要求
FOP 单据优先复用 hzkj_purrefundapplybill，补充履约 / 备货 / RMA 与采购明细关联、处理目的、数量金额及结果回写。
取消采购在原采购单补齐取消范围、审批、进度及关联退货；本地已有未支付取消代码，仍需人工确认 1688 可取消状态、主 / 子单或部分数量能力、原账号与结果核实。确认前不启用自动取消推送。
1688 接口原采购账号校验主 / 子订单、场景及可退范围；审核后推送，保存退款号、物流及实际结果。部分能力、时限和授权须真实联调确认。
采购退款收款复用 hzkj_receive_bill，配置采购退款类型及对应核算逻辑；1688 实际退款成功后自动建单，验证重复同步、补建及部分退款分摊。
岗位工作台采购跟进全部采购退货；仓库只处理实物任务；销售 RMA / 备货回查关联进度。列表、统计与导出按来源授权一致展示。
上线前确认确认审批与客户退款时点、未入库返运路径、全款备货权益及资金转换。先验证单笔来源部分退货、跨入口防重、在途退回与退款异常，再推广。

本方案为待实施设计。本地已有单据及查询基础，不代表退款写入、未入库退回和资金回写已接通；本次不修改业务代码。
