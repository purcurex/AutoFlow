# 账号角色规范

账号管理界面使用四种角色。角色名称不是工作台名称；销售、采购、配货、发运、仓库是五个工作台入口。

| 角色 | 系统管理 | 默认业务范围 | 默认分析权限 |
| --- | --- | --- | --- |
| 管理员 | 组织架构、账号与权限 | 营销中心，可单独限制或关闭 | 角色默认，受 FOP 授权约束 |
| 部门经理 | 不可访问 | 本部门及下级 | 部门范围 |
| 外贸业务员 | 不可访问 | 本人负责的业务，含外部业务伙伴 | 本人范围 |
| 协同管理岗 | 不可访问 | 跨部门待办与订单明细 | 营销中心各业务部门汇总，不开放客户、业务员及个人业绩明细 |

HR、商品管理等未开通业务数据的账号归入协同管理岗，显示“未开通业务数据”。这是数据权限状态，不新增角色，也不因页面升级自动开放业务。系统管理员关闭业务数据后仍保留系统管理。

## 实现约定

- `accountRole` 对外值：`administrator`、`department_manager`、`salesperson`、`collaboration`。从现有数据库字段推导，不新增角色表或批量修改现有账号。
- `User.role=admin` 是系统管理的唯一依据；内部 `businessRole=admin` 仅表示全公司业务范围，不等于管理员。菜单、路由、管理 API 分别校验。
- `businessRole=none` 是业务数据关闭状态。其余既有字段、FOP 绑定和独立资源授权继续生效。
- `PUT /users/:id/account-access` 一次保存角色、业务范围、工作台。服务端事务内重新检查当前管理员，禁止自我撤销管理员角色。请求中的角色与业务范围必须一致；管理员可独立配置业务范围。
- 明确切换角色或从关闭业务状态开通时，应用对应图表模板；协同模板与通讯录初始化共用，仅开放部门汇总。相同角色的普通编辑保留已有图表细项。角色编辑面板选择新角色时默认勾选五个工作台，管理员可在高级配置调整入口；公司业务范围账号按既有规则拥有全部入口。
- 只打开页面、筛选或取消编辑不改变账号；FOP 绑定、账号密码和员工档案仍在组织架构中维护。
- 图表细项是独立的管理员配置入口。数据始终与账号范围及 FOP 独立授权求交，列表中的摘要不参与授权判断。
- 账号列表按角色的筛选在后端分页前执行，查询名称、邮箱或编号沿用原接口；客户端不对当前页假装做全量筛选。
