设计结论

新增一个「业务订单量分析」模块，使用一套查询条件联动 订单趋势 + 区间排名 + 汇总清单。默认查看「组织 → 营销中心 → 按月 → 全部仓库」，一屏回答：总共有多少单、何时产生、由哪些部门／对象贡献。

综合分析保留物流服务商、组织、业务员三类。客户模块单独设置：默认保留前十客户排名，其余客户合计为“其他”；按名称或编码搜索、或点击排名客户后查看该客户的月／周／日趋势。仓库属于独立筛选，不与客户、部门组合成几十个固定报表；选择分仓对比时，把主图拆为杭州仓、深圳仓两张共用刻度的图。原始订单明细始终跳转工作台。

本交付为设计方案与可操作原型，对应正式前端和授权 API 已在本地实现；本文件仍是独立模拟原型，正式接口以 docs/FOP_ORDER_VOLUME_API.md 为准。下方全部为确定性模拟数据，统一截至 2026-10-21；客户为虚构名称，员工沿用现有演示名册，角色为“业务数据管理员”。未调用 FOP。

切换类别、部门、明细对象、月／周／天、仓库，即可联动图表及清单。订单趋势保留完整时间轴，默认定位最新已发生时间段。点击图表或清单中的订单数，可预览工作台应接收的筛选条件。

二、时间轴与统计口径

时间粒度完整数据范围默认可见窗口未结束周期处理
按月当年 1 月至当前月。如 2026-10-21 为 10 组；历史整年为 12 组最近 6 个月，滑块靠右；左拖查看前期当前月标“截至 10-21”，不与完整上月直接计算涨跌
按周本周及前三周，共 4 组；以周一至周日、上海时区划分，可跨月跨年4 周全部展示，不显示多余滚动轴示例 09-28—10-04、10-05—10-11、10-12—10-18、10-19—10-25；末周只累计至 10-21
按天所选月完整日历天数，28 / 29 / 30 / 31 组；默认当月最近 14 个已发生日期，当前日置于右侧；可向左查历史、向右看到月末日期已过去但无订单记 0；未来日期为 null / “未到日期”，灰色标识，无柱无点；今天标“截至当前”

建议默认指标：按订单创建日期统计有效业务订单数，单位“单”；以 FOP 稳定履约订单 ID 去重，不按 SKU 行、商品件数、运单数或 Shopify 展示单号计数。默认包含待支付和已支付，排除已取消、全额退款及明确标识的测试订单；部分退款订单保留 1 单。页面显示口径说明；正式接入前核对 FOP 状态映射。若需要“已发货订单量”，应增加明确指标／日期口径，不能悄悄把创建日期换为发货日期。

时间比较：一期先展示绝对订单量与对象占比，不在未结束周期上误报环比。后续如增加环比，本月对上月同已过天数、本周对上周同星期及时间；分母为 0 显示“—”。独立客户查询沿用相同时间规则。历史月份按选定年份和月份计算，空月份同样占一个时间桶。

归属规则：组织和业务员采用订单创建时归属快照，权限判断仍使用当前授权，避免员工调岗改写历史业绩。服务商／仓库采用订单当前正式确认的主履约归属，并注明“截至更新时间”。一单拆到多个包裹、多个仓库或多个服务商时，须由 FOP 明确唯一主归属；不能确定的进入“多仓／多服务商待归属”，不在每个分类各计一次。未来“包裹量”应为独立指标。

分类完整性：“其他服务商”只收已知但非五大服务商；空值进入“未分配”，未知仓库／组织进入独立待归属分组，不静默丢弃。领导不显示为个人系列；部门内非业务员归属、离职或缺失人员映射的订单用“其他归属订单”汇总，不丢弃、不显示领导姓名。原型数据仅含杭州、深圳两仓；正式接口发现额外分组时，自动展示补充行／卡片，确保分类合计能与总数核对。

三、图表结构与样式

区域推荐呈现作用
概况指标查询区间合计、杭州仓、深圳仓；发现未归属仓则增加提示和数值总量始终对应整段查询区间，拖动缩放、隐藏图例不会改变 KPI
订单趋势 · ECharts 1按月／周用分组柱状图；按天用折线图，禁用平滑以避免虚构日间起伏。汇总和明细为并列系列，不堆叠月份看规模，日期看节奏；所有订单数为整数
分仓对比 · ECharts 1A / 1B杭州仓、深圳仓小倍图；同一时间轴、同一 Y 轴最大值、同一对象顺序与颜色、同步缩放避免“对象 × 仓库”形成十几种颜色；窄屏上下排列
区间贡献排名 · ECharts 2横向条形图，按当前查询区间订单数降序，最多 Top 10；不放汇总行快速找主要贡献者；不是“某个月”的排名
汇总／逐期清单合计行固定第一，其后全部授权对象；字段为对象、订单量、占比、杭州仓、深圳仓；逐期表可展开精确核对数字；真实页面服务端分页／导出，不把 Top N 当全量

颜色语义：汇总系列沿用当前 Dashboard 浅蓝紫 #94A5DD，合计数字使用同色系较深文字 #6478B3，表格汇总底色 #F1F4FC。明细沿用柔和青绿、浅金、粉红、淡紫；其他／未分配使用不同中性灰并明确标签。对象颜色绑定稳定 ID，不因排名或仓库切换变色。选中控件不出现蓝色外框；键盘焦点保留中性灰指示。

Top N：对综合分析中的人员，以整段查询区间排序后固定 Top 5，不能每个月换一批人。“其余对象”补齐剩余贡献，与“其他服务商”完全不同。手选单一对象时直接显示该对象。分仓比较使用两仓共同范围的同一 Top 5，不分别排名。统计清单保留 Top N 与其余合计，原始订单清单支持查询全部授权订单；合计 = 明细之和 = 两仓之和（有未归属项时包含该项）。

提示与下钻：悬浮显示完整对象名、日期范围、订单量、区间状态；汇总永远排第一，数字不加货币符号。点击柱形／折线点／排名／汇总表数字时，在现有授权岗位工作台打开订单清单，携带对象 ID、时间区间、仓库和口径；点击汇总仅带范围，不叠加“全部分类”。排名及区间清单使用完整查询区间，趋势点使用该时间桶。

四、页面归属、权限与预留 API

页面位置：经营概览新增「业务订单量分析」卡片，可展开完整分析区；日常高频分析可在岗位工作台增加同组件入口，下钻筛选通过安全 URL 参数传递。Dashboard 放统计和汇总清单，原始订单编号、客户、SKU、图片、支付状态等订单明细仍由工作台承载。当前待办队列接口不能直接承担“所有订单”的分析下钻，需新增专门的授权清单查询，不用某一待办队列冒充全量。

权限：每次请求先取得会话身份，读取本地业务角色、当前部门／员工绑定和 FOP 数据权限，再计算授权交集。业务数据管理员可看所属公司授权全集；部门经理看本部门及子部门；业务员看本人。汇总、下拉目录、搜索建议、排名、导出、下钻都使用同一范围；无权数据不作为“其他”泄露。界面只能提交筛选对象 ID，不能提交授权用户或权限范围。有限权限的“营销中心合计”必须标“授权范围内”。
