D03 删除核查软删除／作废返回状态与修改时间；硬删除优先复用平台可查询删除记录，否则提供公司全量 ID 清单及按 ID 存在性确认，明确区分不存在、无权与失败。删除和跨公司移出可被识别；普通分页空结果不能作为删除依据。若平台已有能力可复用，无需先建设事务日志。
D04 事实补齐按实体输出完整分录、稳定关联、原生状态和业务员归属；提供未关联履约的独立采购、收货通知、售后等对象。缺失字段明确为空并列清单。同一对象不因所属清单或是否关联当前履约单而漏同步；关系及归属变化可追溯。
D05 联调交付确认源服务器时间、限流、单页上限、超时及时间范围性能；提交各实体操作前后时间样例、过滤与分页配置、全范围核对方式及异常响应。可用现有 API 完成初始化与增量验收；源端持续变化时做差异回查与收敛验证，不伪称同一事务时点完全一致。

05 · 同步机制与业务边界

5.0 · 时间增量机制（首期）

  1. 初始化衔接：开始前记录源服务器时间 T0，按稳定 ID 遍历实体全集并读取完整单据；随后从 T0 减重叠窗口追赶创建和修改变化，再做全量 ID／内容差异核对。该过程最终收敛，不是冻结快照；初始化中发生删除、跨公司移动及异常回填仍走核对补偿。
  2. 固定窗口：每租户＋公司＋实体保存上次成功截止时间 W。本轮 L=W−重叠窗口，U=源服务器时间−安全延迟；createtime 和 modifytime 两路均查询 [L,U)。建议初值重叠10分钟、安全延迟2分钟，须按实测事务延迟、时钟及接口滞后调整；超过窗口的迟提交／回填由补偿扫描修复。U不大于W时不回退水位，源时钟异常需核查；时间精度未经确认不得截断为秒。两时间均空或非法的记录进入核查，不生成当前时间代替。
  3. 稳定分页：每路固定 U，按该路时间 t、主键 id 升序；下一页条件为 t>lastTime 或（t=lastTime 且 id>lastId），同时保留窗口约束。同秒多单不能只传时间游标；ID按源端类型比较，64位ID不转JavaScript数字。这是稳定游标目标；现有四项API采用普通页码时，须显式启用下述最终一致采集模式，不能宣称无遗漏或稳定快照。
  4. 新增与变更：两路合并按租户＋实体＋稳定主键执行 upsert，保留公司归属；若实体主键只在公司内唯一，再纳入公司主键并显式处理移属。本地无记录即新增，有记录即更新，不按创建日期判断是否已入库。同一时间内容变化仍比较规范化内容，不以时间相等跳过。实体串行执行，禁止较旧源时间覆盖已保存的新事实；并发读冲突回读确认。
  5. 持久化与重跑：分页原文、范围及时间先暂存。两路全部成功、所需详情齐全后，事务保存完整原始单据、旧／新关联投影任务并将采集 W 推进到 U（不是本页最大时间）；展示发布须重算新旧关联订单。四实体普通分页模式已实现同事务发布；必需关系缺失的单据保留待处理，不把采集水位等同全部展示已刷新。失败不推进 W，重启从该窗口重读；缺非必要字段可留空，分页或详情缺失不可当作该窗口完整成功。一次完整空窗口可以推进 U，但响应须明确成功及范围。详情读取到U之后的新内容须记录实际时间，不能标为U时点快照；缺省字段不冒充显式清空。
  6. 独立实体：履约、备货、采购、收货、配货、发运、出入库、资金、RMA及人员归属各自取增量。下游单据变化即重算关联订单，不依赖履约单 modifytime 跟着变；取消关联时同时清理旧关系。分录独立修改若不更新主单时间，则补扫对应实体或小范围修补时间更新。
  7. 删除与补偿：软删除／作废作为状态更新；硬删除优先读取平台删除记录。没有删除记录时定期完整 ID 对账，对差异逐ID确认源端不存在／移出后才使本地失效；失败、无权或不完整扫描禁止批量删除。对账期间新增／修改记录需保护，扫描结束再回查差异；补偿与增量共用写入锁，回填旧时间造成的冲突经源端权威回读确认后修正，不能永远被旧时间拒绝规则挡住。每日完整内容轮检为建议起点，可分批调度，但必须覆盖已完成、关闭、历史单据，不能永远只扫近期修改或未完成订单。
  8. 展示及权限：按实体显示最近成功时间、积压和异常。跨单据暂时不一致时保留待核查，不推定齐套／审核成功；本地权限按最新可验证归属重算，改属失败的记录隔离，已知撤权立即生效。审核、库存、预占、逆向始终由 FOP 实时核验；同步不执行这些业务。

字段存在不等于所有写入路径必然更新时间。源码中 PurchasePaidOrderSyncService.savePurchaseOrder 与 OrderBatchModifyService 使用 SaveServiceHelper.update；客户资料 AffiliateMarketingOperationPlugIn 另有直接 DB.update 且该 SQL 未包含修改时间。前者的时间维护行为需在部署版本实测，后者说明关联基础资料不能一概依赖表头时间。应覆盖分录增删、后台回调、审核／撤审、撤销关系、改属、同秒二次修改、回滚及迟提交；发现缺口再定点补齐。

错误响应带 requestId 和稳定错误码，区分认证失败、无权、版本冲突、快照／游标过期、捕获不健康、限流和暂不可用；失败不得包装为成功空列表。scopeVersion 只在范围／授权变化时更新，普通证明续期不无故改变版本。

本地关联已实现，配置核验：WORKBENCH_READ_MODE=local、WORKBENCH_MOCK_ENABLED=false、FOP_QUERIES_PAUSED=true、WORKBENCH_AUTOMATIC_CALLS_ENABLED=false、WORKBENCH_SYNC_ENABLED=false。导航／计划同步及独立自动续验均关闭；FOP暂停也阻止手动回源。未改开关或恢复调用，配置核验不代表远端联调。

验收须分别验证：首屏先本地、筛选翻页不触发同步、同清单重挂载不重复触发、跨用户60秒去重、手动请求取得新屏障、27个每日时点及跨午夜、错过时点合并、任务观察上限、切换账号丢弃旧回执，以及三项暂停开关下零自动回源。最近查询时间不能覆盖采集／同步时点；失败、未知与真实零数据必须可区分。

5.4 · 本地单据关联

已采集事实按单据与完整分录规范保存，复用来源主表、分录表、各类业务主表及关联表，不为五工作台分别复制订单。履约、备货、采购申请、采购、配货、发运、发货通知、出库、收货通知、收款纳入本轮规范化；原始采集记录保留；hz_fop_collected_chains保存构建版本，hz_fop_order_relation_paths保存根单路径，不固化用户可见范围。不同采集批次按采集时间选择整条记录，不拼接旧字段；较新的冲突阻止旧记录恢复关系。

本项目实现规则
关联依据优先源单据ID、分录ID；缺ID时仅使用同实体唯一单号及明确分录行号。ID与单号冲突、来源不唯一或缺失时保留待核查，不按相同SKU认定来源关系。FOP空引用0按缺失处理。
统一查询GET /api/workbench/orders/:orderId/business-chain，orderId为FOP履约订单内码。先按当前本地账号、组织与员工绑定核验根单，再查询可验证的下游链；返回前复核权限变化。接口只读，前端业务链展示入口尚未增加。
合并单隔离共享采购、收款单只返回本订单关联分录及已知分摊值，不返回其他订单商品、原始完整载荷或合并单总额。分摊未知返回空值，不分配整单金额。
重建与过期npm run workbench:chain:rebuild显式离线重建；支持-- --dry-run。内容哈希相同则复用；变化时同事务更新自有规范化数据，保留稳定主键，仅移除消失的分录和关联。采集批次发生变化后接口拒绝旧索引，须重新构建；本轮未增加自动重建任务。
实现边界非一致采集快照，源版本未知，未证明源端删除。使用禁用的离线连接与独立未发布数据集，不激活正式副本；不能作为审核、库存或同步完成依据。RMA统一链、入库、付款、收款调整及实物采购退货关系仍待接入或补齐来源。

业务链专项工程验证记录（business-chain-verification.json）尚未提供，验收证据待补。FOP仍须交付稳定版本、源单及分录关联、分摊与删除／解除变化；本地关系可查询不代表六项正式同步服务已接通。

验收项通过标准
T01 初始化衔接全实体 ID 遍历期间制造新增、修改与删除；T0起追赶并核对后均可定位，独立单据不漏。结果标明最终一致，不标为事务快照。
T02 时间覆盖逐实体验证保存、审核／撤审、接口、导入、回调、分录增删、取消关联。全部变化可由时间查询或明确补偿检出；空值清除旧值，完整分录替换不残留。
T03 分页恢复同一时间超过一页、边界时间等于U、同秒二次修改、重复两路命中、半页失败、详情失败、事务失败及进程重启均验证；失败不推进W，重跑不重复生效。
T04 归属变化业务员改属、人员停用和公司移动进入同步及本地权限重算；集成撤权明确失败，不能当空数据删除。普通用户按本地员工绑定筛选，不增设FOP逐人授权。
T05 核对补偿硬删除、回填早期时间、修改时间未变、超过重叠窗口的迟提交均由完整扫描发现；未完整扫描或无权不删除本地记录。按ID及内容核对，金额分币种；持续变化时记录差异与重查结果。
T06 工作台覆盖提供五工作台各阶段真实样例，含RMA、备货、未齐套／齐套待审、采购部分发货、部分入出库与取消；未全出库订单在待办或异常清单可定位。实物退货缺源时明确未通过，不报全功能完成。
T07 业务隔离全量、增量及重放均不触发采购／配货／锁库／退款；审核等实际操作产生可追踪变更，实时库存返回当前事实。
T08 容量与发布实测时间范围性能、同秒峰值、最大单据、停机追赶和完整轮检成本；据此确定周期、延迟与重叠值。记录实体水位／错误，完整执行前保持自动调用暂停。

交付顺序：先复核原生时间和既有查询配置，再补最小接口缺口及遗漏更新时间的路径，最后逐实体联调时间增量与补偿。只有严格事务历史或时点核对成为必要目标时，才启用六服务扩展。未提供字段、实体或能力标记待提供；已有数据仍可展示。当前自动同步保持暂停，完成联调并另行安排后启用。
