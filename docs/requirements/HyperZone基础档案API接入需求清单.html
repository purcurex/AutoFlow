2026-11-17 v1.0 · 接口评审方案

01 · 接入范围与分期

本方案用于FOP与HyperZone本地查询库的基础档案接口评审。目标是建立稳定的客户、店铺、商品权限目录，减少页面实时调用，并支持后续档案变更增量同步。本期先补权限和查询必需数据，二期补映射及扩展分析。这是接口需求方案，不代表接口已发布、数据已全量入库或自动同步已启用。

采用“FOP业务事实 → 集成账号读取 → 本地档案与关系 → 后端权限过滤 → 前端展示”。复用现有OpenAPI与本地组织体系，优先增加字段和查询条件，不要求为每张表开发一套专用服务。本方案不重新开放定时调用；正式启用另按限额和验收结果安排。

阶段接入内容交付结果
本期接入公司／部门；员工／FOP账号绑定；客户；店铺；SKU精简档案；商品精简档案；仓库账号可查客户范围本地化，支持备货库存客户授权、私有SKU隔离、店铺与仓库筛选。
二期完成店铺SKU映射；物流商／渠道；供应商精简档案；供应商SKU映射；组合商品关系；可选库存分析快照补齐商品关联排查、物流分组、采购检索及历史库存分析，不改变实时业务执行依据。
暂不接入平台Token／密钥、完整营销素材、无业务用途的商品长描述、钱包与授信明细、全量价格规则不因同步档案而复制无关数据；新增明确用途后再单独定义字段与权限。

本文件为独立评审附件。共同契约仍为《HyperZone智能办公平台项目开发需求说明书》；本方案未实施部分统一标记待接入，不把元数据确认、数据库预留或Mock成功视为真实接通。

02 · 所有接口共用的字段与时间要求

下列字段适用于本期与二期的每一种实体及独立关系记录。英文名称为建议响应别名，不宣称等同FOP现有字段编码；接口方须提供实际字段编码、类型、时区、精度和样例报文。

字段要求同步规则
来源身份sourceEntity、sourceId；ID使用字符串，不能以名称或SKU文本代替主键。本地唯一键至少包含来源系统、租户、实体、源ID；按源实体是否组织内唯一补充组织维度。
组织范围tenantId、所属组织／公司ID；共享档案另提供适用组织集合或组织关系。明确“所属组织”与“可使用组织”含义，不把缺组织字段解释为全公司共享。
编码、名称number、name；多语言名称优先提供zh_CN，必要时附原名。更名保留稳定ID，禁止按名称建立权限关系。
createdAt 创建时间所有实体必返，真实原生创建时间，不得以采集时间替代。已知客户注册使用createtime；其他实体字段码待逐项确认。用于首次建档、注册统计与审计；不能作为后续变更增量条件。历史无值明确返回null并列入质量缺口。
modifiedAt 修改时间所有实体必返，覆盖字段、状态、归属及关系变化。实际字段码及保存行为待逐项核验。作为增量主依据。必须可按修改时间范围查询，时间相同时按稳定ID排序；不能无条件用创建时间或当前时间填补。
时间格式带时区的ISO 8601；允许源端固定UTC+8格式，但必须书面声明，由适配层规范化。保留源实际精度。本地时间字段统一存储时间点，展示UTC+8；禁止伪造毫秒精度。
状态与删除原始状态值及名称、有效／停用标识。删除需deletedAt或独立删除清单；至少具备完整核对机制。停用、解绑、软删除也必须更新modifiedAt；硬删除不能只依赖“修改时间查询”。
关联字段关联实体类型、ID；名称仅作展示。多对多关系返回稳定关系ID或明确唯一组合。关系新增、迁移、删除必须可追踪。订单客户、会员客户、财务客户若属不同实体，须显式提供映射。
来源证据响应记录查询窗口、分页位置、是否还有下一页；明确成功、失败和无权限。本地记录采集时间、批次、接口版本及校验结果。采集时间与业务创建／修改时间分开保存。

历史记录modifiedAt为空时，不静默纳入正常增量水位。优先由FOP修复可靠更新时间；暂不能修复的实体单独完整核对并标记“不支持可靠增量”。首采可保留原始缺口，但不能据此通过增量同步验收。

03 · 本期接入API清单

本期共7类数据。表中“创建／修改”均为必须提供；每一类还须满足第二节公共字段。来源已确认只表示本地源码或元数据存在，不等于当前测试环境接口已完整支持。

编号／数据必须提供的业务字段创建／修改与增量触发本地用途／来源状态
P1-01
公司、部门		组织ID、编码、名称、父组织ID、组织类型、公司归属、有效状态；共享业务范围。创建时间、修改时间；新增、更名、迁移父部门、公司调整、启停均更新修改时间。复用本地组织表；明确层级和公司边界。现有组织映射可复用；FOP正式实体、时间字段及增量API待确认。
P1-02
员工、业务账号绑定		员工ID、姓名、英文名、当前业务部门、任职／启停状态；FOP用户ID与员工ID映射。多任职须声明主业务部门或有效关系。员工和独立账号绑定均提供创建时间、修改时间；调岗、离职、账号停用、绑定变更更新修改时间。建立账号→员工→部门权限基础。不能假定bos_user ID等于员工ID；现有绑定逻辑可复用，映射增量来源待核验。
P1-03
客户档案		客户ID、编码、名称、公司／使用组织、当前业务员账号ID、状态；如有独立财务客户ID同时提供对应关系。创建时间、修改时间；业务员转移、名称、状态、所属组织变化均更新修改时间。必须可查询无订单客户。客户下拉、备货库存授权及当前客户归属。已确认hzkj_member_customer、hzkj_biz_user；现有注册采集表可作为种子，完整档案与变更覆盖待验收。
P1-04
店铺档案		店铺ID、编码、中文名称、平台、平台店铺ID、域名、所属客户ID、店铺业务员账号ID、绑定／有效状态；实际业务需要的币种。创建时间、修改时间；更名、换客户、换业务员、绑店／解绑、启停更新修改时间。店铺权限与筛选、同名区分。已确认hzkj_shop_record、hzkj_customer、hzkj_user；正式档案API及时间字段待确认。不返回Token。
P1-05
SKU精简档案		SKU ID、编码、所属商品ID、属性值、图片地址、对应物料ID、单位、公有／私有、所属客户ID或客户集合、有效状态。创建时间、修改时间；公私有转换、客户归属、属性、图片、物料关联、启停变化更新修改时间。客户集合变化不得漏报。库存检索和私有商品隔离。元数据入口hzkj_sku_record，已有hzkj_public、hzkj_cus；实际查询实体、客户关系基数及枚举待接口确认。
P1-06
商品精简档案		商品ID、编码、中文名称、商品载体、类型、有效状态；分类仅取当前查询需要的ID／名称。创建时间、修改时间；名称、实物／虚拟载体、类型、启停变化更新修改时间。SKU基础解释及商品类别识别。元数据入口hzkj_good_record，hzkj_good_carrier已存在；正式查询实体和时间字段待确认。历史订单优先本单商品事实。
P1-07
仓库档案		仓库ID、编码、名称、公司／组织ID、有效状态、适用组织；若有岗位仓库授权，提供独立授权关系。创建时间、修改时间；组织迁移、更名、启停及授权关系变化更新修改时间。仓库筛选和范围校验；展示统一HangZhou／ShenZhen，关联使用ID。正式源实体及更新时间字段待确认。

本期开发交付

  1. 对照现有API确定7类数据的实际实体、主键、时间字段、关联实体类型和状态枚举；输出字段映射及成功样例。
  2. 支持首轮完整分页与修改时间增量；验证关联变化、停用和删除处理。
  3. 本地客户目录接管客户选择器；库存请求必须校验所选客户、SKU、仓库范围。
  4. 权限关联变更发布后更新权限版本，清除旧客户选项、列表及导出缓存；权限冲突进入核查。

04 · 二期完成API清单

二期接口也必须具备创建时间、修改时间及关系删除处理。实际开发顺序按功能需求确定，不因档案齐全而自动新增业务执行能力。

编号／数据必须提供的业务字段创建／修改与增量触发适用边界／来源状态
P2-01
店铺SKU→本地SKU映射		映射ID、客户ID、店铺ID、平台、平台商品／变体ID、源SKU、本地SKU ID、状态；若为组合映射，返回目标明细及换算数量。创建时间、修改时间；新关联、改绑、解绑、失效、目标SKU或组合数量变化须可同步。明细变更更新父映射时间或提供关系增量。未关联SKU排查。元数据存在hzkj_sku_channel_mapping；正式实体及稳定店铺／变体关联字段待确认／提供。不能只用源SKU文本跨店匹配，不以映射授予客户权限。
P2-02
物流商、物流渠道		分别提供物流商ID／编码／中文名称／状态；渠道ID／编码／中文名称／所属物流商ID／状态／组织范围。两类档案分别返回创建时间、修改时间；更名、渠道换物流商、启停及范围变化更新修改时间。统一物流展示和分析分组；单据有正确名称时仍使用本单事实。档案实体与API待确认，不同步整套报价规则。
P2-03
供应商精简档案		供应商ID、编码、名称、平台及平台商家ID、有效状态、组织范围；业务需要的旺旺联系标识。创建时间、修改时间；名称、平台身份、联系标识、组织、启停变化更新修改时间。采购检索与联系入口。现有采购单信息足够时无需等待此接口；联系方式继续按业务上下文授权，档案API待确认。
P2-04
供应商SKU映射		关系ID、供应商ID、平台商品／规格ID、本地SKU ID、单位及换算系数、有效状态、适用组织。创建时间、修改时间；改绑、换算系数、失效及关系删除须进入增量。采购SKU核对。元数据入口hzkj_sku_supplier_mapping；正式字段、基数与接口待确认。不默认同步成本和价格历史。
P2-05
组合商品、包装关系		关系ID、父商品／SKU ID、子SKU ID、数量、单位、关系类型、有效状态；有效期如源端存在则提供。关系创建时间、修改时间；新增／删除子件、数量及包装变化必须更新父记录修改时间或发送关系增量。扩展商品结构查询。商品元数据已有子件入口；正式关系API待确认。订单明细已有展开事实时以本单为准，不用最新BOM重写历史订单。
P2-06
库存分析快照（可选）		库存池ID、客户ID、SKU／物料ID、仓库ID、公共／客户专属、全款／押金类型、在库／占用／可用数量、单位、业务快照时点asOf。库存记录创建时间、源业务修改时间；余额归零及记录删除必须可见。若源为计算视图无原生时间，需提供变更序列或可验证全量快照，不能以查询时间伪造修改时间。仅供历史分析和时点查询，不替代实时可用库存。数据源及接口待提供；实时库存查询仍走独立已授权接口。

二期所有关联字段必须先通过本期档案范围核验。已知私有SKU但客户关系缺失、映射冲突或目标档案缺失时，不自动扩大权限；保留原始数据并标记待核查。

05 · 创建时间、修改时间与增量同步契约

查询接口最低能力

能力明确要求
首次全量按授权组织完整分页，包括停用记录；不能限定近一月、仅有订单客户或仅在用SKU。记录起始水位，首采后重放重叠窗口补齐扫描期间变化。
增量过滤支持modifiedFrom（含）与modifiedTo（不含）；每轮固定上界。仅提供createdFrom不满足档案增量需求。
稳定翻页优先按(modifiedAt, sourceId)升序提供游标；已有页码API可复用，但须固定时间窗、确定排序并采用重叠重放和周期核对，不能宣称一致快照。
同秒与迟到同时间戳多条不能漏。重叠窗口和安全延迟根据源精度、提交延迟实测配置；仅时间游标且无稳定ID不可直接验收。
提交水位本轮全部分页校验、落库和查询投影发布成功后才推进；失败、限流、无权限时保留旧水位，重试幂等。
批量与限额提供最大页长、速率上限、限流错误与重试建议；按实体串行或低并发同步。批次补齐关系，避免逐客户／逐SKU查询造成N+1调用。
实体更新保留原始报文及源时间；按稳定身份幂等更新。缺键不等于清空，显式null与关系空集合必须有明确含义；不完整响应不得擦除已采事实。
关系删除必须声明响应是完整关系集合还是差量。完整集合允许替换当前关系；差量必须提供新增／移除操作及变更时间。
硬删除优先删除清单／墓碑；否则对完整授权范围做周期核对。扫描未完成、筛选改变、权限缩小、接口失败不能当作删除。
权限变更发现客户／店铺转移或员工停用后，更新本地权限版本并失效旧缓存。尚未同步到的源端变化存在延迟；即时撤权需源端通知或定向同步能力。

必须核验的源端保存路径

  • 界面保存、批量更换业务员、导入、后台插件、定时任务、API更新，均须推进原生modifiedAt或可消费的变更序列。
  • 分录、子件、公私有客户集合、共享组织范围变化，须推进父档案modifiedAt；不能推进的提供独立关系时间增量。
  • 创建后无修改的记录应有有效modifiedAt；只有确认源端语义才允许与createdAt相同，适配层不能自行推定。
  • 禁用、重新启用、解绑、软删除均进入增量；硬删除、未更新时间的路径和迟到变更由删除流或完整核对补偿。

同步频率与图表缓存分开配置。建议先验证单次全量和定向增量，再按FOP调用预算确定档案同步周期；客户归属、员工启停优先于名称与图片更新。图表工作时间30分钟／非工作时间2小时的缓存策略不能替代权限撤销机制。正式自动同步继续保持暂停，方案本身不启用任务。

06 · 权限、数据隔离与转移规则

场景采用的依据后端必须执行
客户列表、备货库存客户当前业务员→已核验FOP账号／员工映射→当前个人或部门范围。客户选项查本地；收到customerId仍再次校验。所选客户、SKU、仓库先授权再查询，分页、合计及导出同范围。
部门经理默认个人；切换部门范围后查询授权部门成员名下客户。不以部门名称匹配，不把“能看部门汇总”自动升级为“能看部门所有客户明细”。
协同岗位岗位权限与授权业务范围。采购／仓库可办任务不等于可浏览全部客户、店铺或私有商品档案；按授权上下文返回必要字段。
店铺与映射客户归属、店铺自身业务员和明确授权规则。归属冲突不取权限并集；店铺解绑或转移后重算可见关系。源SKU必须带店铺／平台上下文。
SKU与库存池公有／私有目录与客户库存归属分别判断。公有SKU不能开放所有客户该SKU的备货余额；未知公私有不默认公开。
业务单据对应FOP单据自身归属和原生业务状态。档案更新不擅自覆盖单据字段；源端实际回写后随单据增量更新。历史业绩归属不由客户表简单覆盖。
归属转移FOP更换业务员源码会更新客户、店铺、关联履约订单等记录。发现转移后优先刷新受影响关系及单据，发布一致的权限版本；已发现冲突但尚未完成同步的数据暂缓普通账号访问。不能仅更新客户表后继续复用旧缓存。
缺归属／停用／同步失败归属与完整性状态必须明确。缺归属进管理员核查，不向普通账号放开；停用禁止新增授权，历史只读按明确业务规则；同步延迟不得冒充实时权限。

当前项目已有客户注册采集表及业务账号→员工映射，可复用数据作为首采种子，但完整档案范围、归属变更与增量覆盖仍需验收。备货客户选项的真实数据分支目前调用实时接口，本期目标是将目录查询改为本地；库存数量继续按已授权客户池实时查询。集成账号负责获取公司范围事实，普通用户权限由本地后端计算。

07 · API交付与验收清单

检查项通过标准
字段清单逐实体提交实际实体编码、字段编码、类型、可空性、创建／修改时间字段、时区精度、状态枚举与关联实体类型；缺项标待提供。
真实接口提供已发布接口地址／操作名、授权范围、请求参数、成功／空结果／失败／限流样例；不能以元数据文件或Mock替代。
新增与普通修改新增档案被首采／增量捕获；仅修改名称或图片也能捕获；原创建时间不变，修改时间推进。
归属与启停客户A业务员转B后，权限更新后A不再可查该客户池，B按范围可查；店铺、员工、SKU状态变化同样可同步。
无业务单据档案新客户无订单、新SKU无库存仍能完整接入；零库存与无权限不能混淆。
分录／关系仅改客户集合、组织共享关系、子件数量或映射目标也能捕获；删除一条关系不删除其他关系。
分页与恢复同秒多页、处理中源端新增／修改、重叠重放、重复请求、失败续传均不丢记录；水位只在成功后推进。
删除与缺口停用、软删、硬删可识别；全量未完成不误删；时间缺失、权限变化、响应缺键不伪造成零值或空权限。
隔离与缓存跨客户、跨公司、私有SKU、篡改customerId、分页与导出越权均被拒绝；转移后的旧缓存不能继续返回已撤销数据。
调用与业务影响记录全量／增量调用次数、限流及耗时；同步只读，不触发付款、审核、采购、配货、锁库、Shopify履约或业务回写。

建议每个实体独立验收与记录水位。未通过可靠增量验收的实体继续保留“待接入／受控完整核对”状态，不拖延已经具备完整条件的其他实体，也不宣称全量接通。
