四色系与深浅主题统一规范

2026-11-18 1.2

01 视觉资产范围

商务蓝、清新绿、典雅紫、活力橙四种色系，各含浅色与深色，共八套。新浏览器默认商务蓝浅色；用户在个人设置切换，即时生效并保存在当前浏览器，刷新后恢复。覆盖五个工作台、Dashboard、客户业务、组织、权限及个人设置。

保留现有公司 Logo、Dashboard 五张渐变卡片及深色配色。成功、警告、危险保持业务语义；品牌色用于主操作、导航、选中、链接与通用图表系列。

浅色模式侧栏选中项使用独立同色系柔和底色与浅色文字，降低选中块和侧栏背景的明暗反差；橙色浅色侧栏提亮为 #48362F，选中底色 #60483E。深色主题使用暖棕侧栏与柔和珊瑚橙。

03 统一组件规范

组件规范
主操作btn-primary / workbench-primary；primary 背景，on-primary 文字，primary-strong 悬停。
次操作、导出、同步中性表面与细边框，同步入口低强调。
选中、链接selection-surface / selection-text / link；浅色小字不直接采用金橙按钮色。
输入、列表、弹窗共用 surface、surface-muted、text、text-secondary、border；控件高 38–40px，圆角 6–8px。
图表主题切换只重绘，不重新查询数据；通用本期/上期配色跟随主题，业务类别色保留。

04 工程资产与后续开发

唯一色值源：frontend/src/theme/palettes.json。执行 python3 scripts/build-theme-assets.py 生成 palettes.css。公共组件规范为 theme/components.css；useTheme.ts 和 theme-init.js 负责选择与首屏恢复。

已确认效果设计保存在 docs/designs/ui-four-themes-v2，实际运行截图保存在 docs/design-system/screenshots。新增功能必须复用语义变量与共用组件，覆盖八种组合，不新增独立品牌操作色或按主题复制页面。状态、业务分类颜色及品牌原图保留独立语义。

05 验证记录

主题启动恢复、八种组合、按钮文字对比度、设置页面、登录主题及国际化测试通过；前端生产构建通过。八套设置页截图来自本地实际运行界面。

全量前端测试：119 个文件通过、3 个失败、2 个跳过；1109 项通过、9 项失败、2 项跳过。失败集中在 FopOrdersView、WorkbenchGlobalSync、WorkbenchRefreshNavigation 的审核状态、审核弹窗和导航预期，保留待业务模块核查；本轮视觉变更未修改审核逻辑。

图表与列表文字可读性修复

修正客户注册及业绩图表、环比摘要、趋势弹窗中将表面色或边框色用作文字颜色的问题。标题、筛选值、列表正文统一使用 color-text，说明使用 color-text-secondary，按钮使用 on-primary。构建检查禁止文本使用背景或边框变量，包括错误的嵌套回退。八套主题正文与卡片表面对比度进行自动验证；本地实际检查浅色与深色图表并保存截图。

部门业绩立柱主题统一

未显式指定系列颜色的图表使用共享主题色序列，首系列与部门汇总立柱统一采用当前主题主色。已指定的业务分类颜色保留；主题切换仅重绘图表，不重新查询数据。覆盖四色系深浅模式的默认立柱与部门汇总颜色一致性测试。
