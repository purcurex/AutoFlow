04 · 安装与空库构建

以下命令均在解压后的资源包根目录执行。Linux使用node/npm；Windows将npm替换为npm.cmd，或使用随包PowerShell入口。生产依赖含平台二进制，必须在目标服务器安装，不能复制macOS的node_modules。

# 解压前核验ZIP的SHA256（Linux）
sha256sum -c HyperZone-Production-VERSION.zip.sha256
# Windows: Get-FileHash -Algorithm SHA256 .\HyperZone-Production-VERSION.zip
node scripts/deployment/verify-package.mjs
npm ci --omit=dev
# 将deployment/.env.production.example复制为backend/.env，填写数据库、JWT、SMTP等
node scripts/deployment/production-readiness.mjs
node scripts/deployment/migrate-compiled.mjs show
node scripts/deployment/migrate-compiled.mjs run
node scripts/deployment/migrate-compiled.mjs show

数据库先由运维创建独立空库和迁移账号；可采用现有PostgreSQL或deployment/docker-compose.postgres.yml，并填写postgres.env。DB_SYNCHRONIZE=false、DB_MIGRATIONS_RUN=false保持不变。迁移按each执行，允许并发索引在事务外创建；重复执行仅运行未应用迁移。若并发索引中断，先检查pg_index.indisvalid和迁移表，定位无效索引并由DBA修复后重试，不直接重跑全部DDL。包内schema-reference.sql仅供结构核对，禁止与迁移同时导入。

# 初始管理员：在backend/.env中填入ADMIN_BOOTSTRAP_EMAIL、USERNAME、PASSWORD与PRODUCTION_ORGANIZATION_NAME
# 密码至少6位，包含字母和数字，最多72字节；ENABLE_ADMIN_BOOTSTRAP保持false
node scripts/deployment/initialize-production.mjs admin --execute
# 命令成功后删除ADMIN_BOOTSTRAP_PASSWORD，保留管理员邮箱用于创建批次
node scripts/deployment/verify-runtime.mjs

账号密码统一为至少6位，包含英文字母和数字，UTF-8编码长度最多72字节。不要求大小写混合或特殊符号，允许使用特殊符号。规则适用于部署初始化、注册、员工开户和密码重置；已有账号的登录密码不因规则调整而变更。

管理员命令创建本地管理员和组织根节点，密码仅散列入库，不创建任何FOP身份绑定。重复命令不重置已有密码；账号冲突会拒绝执行。verify-runtime在独立端口启动验证实例，强制暂停源端调用和自动同步，只检查数据库、打包前端与HTTP安全响应；验证后退出。

05 · 生产范围、首次采集与增量启用

收到正式固定值及凭据后填写backend/.env：NODE_ENV与WORKBENCH_TIMESTAMP_ENVIRONMENT均为production；两组认证配置一致，源站必须HTTPS且与允许源站完全一致。FOP_ORGANIZATION_NUMBERS按JSON对象填写，例如{"生产公司ID":"生产组织编码"}，不是组织编码数组。填写FOP_DATA_MODE=kingdee、目录及实际办理所需已发布API，空接口留空并记录影响，不填写猜测地址。

# 此阶段仍保持暂停和全部自动开关false
node scripts/deployment/production-readiness.mjs --require-source
node scripts/deployment/initialize-production.mjs batch --execute

batch命令按正式生产范围创建一个空活动采集批次，仅记录准备时间；采集时间、水位、订单与权限验证结果在相应操作完成后写入。同范围重跑复用；不同公司、组织编码或账号归属冲突拒绝。首次采集前工作台显示待初始化，业务数量在采集完成后统计。

# 完成配置、源端订阅与身份范围确认后，改为以下值
FOP_QUERIES_PAUSED=false
WORKBENCH_COLLECTED_ENABLED=true
WORKBENCH_AUTOMATIC_CALLS_ENABLED=true
WORKBENCH_SYNC_ENABLED=true
WORKBENCH_TIMESTAMP_SYNC_ENABLED=true
WORKBENCH_READ_MODE=local
WORKBENCH_MOCK_ENABLED=false
# 先在应用服务未启动时显式执行一轮；生产值完整前不要执行
node --max-old-space-size=8192 scripts/workbench-scheduled-sync.mjs --execute
# 核查完成后再启动常驻服务
npm start

首次无水位时执行四实体全量初始化；已有水位则增量，超过24小时执行全量核对。每日UTC+8共27时点，后台每15秒只查本地是否到期，请求起始间隔不低于500毫秒。正常查询、详情、统计和导出读本地；审核、办理和特定库存查询实时访问FOP。失败不推进水位，实体独立退避；429及长503按源端冷却停止本轮。重启不清水位、不复制另一环境的批次，不循环人工执行全量。

检查每实体水位、运行记录、最后成功时间、错误码、待关联数量，以及实际业务样本。普通分页上限1000页/10万条，超限失败保留旧数据；生产数据超过上限时必须先完成分窗或稳定游标适配。四实体之外的数据必须另行完成生产首次采集和验证，不能从本地测试库搬运业务数据替代。

06 · 常驻运行、备份与回退

Linux可使用deployment/hyperzone.service.example，修改安装路径、Node路径与系统服务账号后安装；Nginx模板须补正式域名和证书。工作目录必须为backend，.env权限600。uploads放持久目录，以链接接入各版资源目录。当前先部署单应用实例；数据库锁只避免同步重叠，不能代替完整的多实例容量与调度验证。

Windows使用scripts/deployment/start-production.ps1启动；通过受管理服务或运维任务托管，设置崩溃重启与日志轮转，勿依赖交互终端长期在线。上线前核验健康接口、HTTPS首页及浏览器静态资源；业务API跨域、上传路径和备份权限随目标机验证。

# 使用受保护的PGPASSFILE或交互密码，不在命令行/仓库写密码
pg_dump -h DB_HOST -p 5432 -U MIGRATION_USER -d DATABASE -Fc -f backup.dump
# 恢复到新建的独立数据库，勿覆盖在线库
createdb -h DB_HOST -p 5432 -U MIGRATION_USER RESTORE_DATABASE
pg_restore -h DB_HOST -p 5432 -U MIGRATION_USER -d RESTORE_DATABASE --no-owner --no-privileges backup.dump
# uploads与配置另行加密备份，数据库备份不能替代附件备份

升级前等当前同步批次结束，停止服务，备份数据库、uploads和旧版本配置，再切换资源目录并执行迁移。失败时停止新服务，恢复旧资源与对应备份数据库；不要对数据变更后的库盲目执行迁移down。恢复目标库先核验迁移记录、订单数量、权限与采集水位，再开放入口并恢复调度。原始事实、水位和待补任务不能因回退而单独删除。
