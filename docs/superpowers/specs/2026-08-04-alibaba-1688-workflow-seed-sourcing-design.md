# 1688 工作流种子寻源最小实现设计

日期：2026-08-04
状态：用户已确认方案，待书面复核

## 1. 目标

以“创建搜客工作流”时保存的产品种子作为唯一寻源输入：

- 产品关键词工作流使用关键词调用 1688 关键词寻源。
- 产品图片工作流使用公开可访问的 HTTP/HTTPS 图片 URL 调用 1688 图片寻源。
- 返回适合 Dropshipping 采购评估的 1688 商品与供应商，并按照已有分页机制展示。

本次只完善上述业务闭环，不新增结果页上传入口，不改变客户发现、客户联系方式、`contactScore` 或客户综合评分逻辑。

## 2. 已选择方案

采用“保留显式种子类型”的最小方案：继续使用现有 `seedType` 和 `seedValue` 数据结构。

- `seedType=keyword` 时，`seedValue` 是产品关键词。
- `seedType=image` 时，`seedValue` 是公开图片 URL。
- 不在后端根据字符串形态自动猜测类型，避免普通关键词中包含 URL 片段时产生歧义。
- 不增加一次性搜索接口，不绕过工作流记录直接调用 1688。
- 现有创建页文件上传能力不扩展、不迁移；如果继续使用该能力，其最终保存的 `seedValue` 仍必须是提供方可访问的公开图片 URL。

未采用的方案：

1. 单输入框自动识别关键词或 URL：界面更少，但会改变现有类型选择、校验和修订语义。
2. 在 1688 结果页增加上传/搜索入口：会产生脱离工作流的输入，不符合本次确认的业务边界。

## 3. 配置与启动判断

后端只从服务端环境读取 1688 凭证，前端不得接触密钥。

本地配置文件：

```text
backend/.env.alibaba1688.local
```

启用真实寻源需要同时满足：

```dotenv
ALIBABA_1688_ENABLED=true
ALIBABA_1688_APP_KEY=<app-key>
ALIBABA_1688_APP_SECRET=<app-secret>
ALIBABA_1688_ACCESS_TOKEN=<authorized-access-token>
```

后端在进程启动时加载配置并执行校验：

- 启用开关为 `false` 时，提供方状态为 `not_configured`。
- 启用开关为 `true` 但必填凭证缺失时，后端启动失败并指出缺失配置。
- 凭证不得写入前端、数据库快照、日志或 Git 提交。
- 修改本地凭证后必须重启后端进程。

当前项目不在本次范围内新增 OAuth 管理页面或 Token 自动刷新服务。AccessToken 由已授权的 1688 开放平台流程取得后写入服务端本地配置。

## 4. 数据流

### 4.1 创建工作流

前端提交现有工作流字段：

```text
seedType: keyword | image
seedValue: 产品关键词 | 公开图片 URL
```

后端保存经过 `trim` 的 `seedValue`，并保留现有所有者隔离和工作流修订机制。

图片种子必须满足：

- 协议是 `http` 或 `https`。
- URL 格式合法。
- 执行寻源时能够由后端访问并下载为受支持的图片。

### 4.2 启动寻源

搜客工作流执行到现有寻源 sidecar 时：

1. 检查 1688 配置是否就绪。
2. 按 `ownerUserId + workflowRunId` 加载当前用户的工作流。
3. 根据 `seedType` 创建寻源任务和第一页分页任务。
4. Worker 异步调用 1688，避免阻塞工作流主请求。

配置未就绪时仅跳过 1688 sidecar，不伪造商品，也不使客户发现主流程失败。

### 4.3 关键词分支

关键词分支调用现有 `Alibaba1688Service.searchByKeyword`：

```text
keyword = workflow.seedValue.trim()
beginPage = 当前页码
pageSize = 当前分页大小
```

提供方方法由后端配置决定，当前默认映射为 `product.search.keywordQuery`。

### 4.4 图片 URL 分支

图片分支执行：

1. 后端安全下载 `workflow.seedValue` 指向的公开图片。
2. 校验协议、重定向目标、内容类型、文件大小和图片格式。
3. 归一化图片后调用 `product.image.upload` 获取 `imageId`。
4. 使用 `imageId` 调用 `product.search.imageQuery`。
5. 同一次搜索后续分页复用已保存的 `imageId`，不重复上传图片。

公开图片 URL 本身不直接作为 `imageQuery` 参数，因为当前接口契约要求先取得 `imageId`。

### 4.5 结果展示

结果继续使用现有独立寻源表和分页接口：

- `sourcing_searches`
- `sourcing_search_pages`
- `sourcing_offers`
- `sourcing_suppliers`

前端结果页只负责展示当前工作流的寻源状态、商品、供应商和分页控件，不提供新的种子输入。

## 5. 本次代码改动范围

只允许以下改动：

1. 补齐或强化创建工作流时公开图片 URL 的校验和错误提示。
2. 验证工作流保存的关键词/图片 URL 被原样、正确地映射到寻源任务。
3. 修复 `not_configured` 状态被分页 `pending` 误判成“寻源中”的问题，并停止无意义轮询。
4. 增加相应的前端、后端自动化回归测试。
5. 补充必要的配置说明，不提交任何真实凭证。

明确不改：

- 不新增货源页上传入口。
- 不删除或扩展创建页已有的图片文件上传能力。
- 不新增 OAuth 页面、Token 存储表或自动刷新服务。
- 不改变客户发现阶段顺序。
- 不改变现有分页表结构、评分模型、客户评分或联系方式逻辑。
- 不修改与 1688 无关的模块。

## 6. 错误处理

- 配置缺失：返回 `not_configured`，停止轮询，不调用 1688。
- 图片 URL 非法：创建工作流时返回明确的参数错误。
- 图片无法访问或内容非法：寻源任务记录可解释的图片错误，不影响客户发现主流程。
- 1688 超时或临时失败：继续使用现有 Worker 重试、租约和幂等机制。
- AccessToken 无效或过期：记录脱敏错误并将寻源标记失败，不泄露 Token。

## 7. 测试与验收

自动化测试必须覆盖：

1. 关键词工作流把 `seedValue` 传给关键词寻源参数。
2. 图片工作流接受合法公开 URL，拒绝非法协议或无效 URL。
3. 图片 URL 下载、上传后仅使用返回的 `imageId` 调用图片寻源。
4. 同一图片搜索翻页不重复上传图片。
5. 配置未就绪时不启动真实寻源、不持续轮询、按钮不显示“寻源中”。
6. 现有分页、工作流创建和客户评分测试保持通过。

验收场景：

- 创建关键词工作流并启动后，可在 1688 货源页看到对应商品和供应商分页结果。
- 创建公开图片 URL 工作流并启动后，可看到以该图片为种子的分页结果。
- 关闭 1688 开关或移除 Token 后，页面快速显示“未配置”，无持续请求假象。
- 代码和日志中不存在真实 AppSecret、AccessToken 或签名。
