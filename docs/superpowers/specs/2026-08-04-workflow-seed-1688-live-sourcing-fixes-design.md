# 搜客工作流回显与 1688 真实寻源修复设计

日期：2026-08-04
状态：用户已授权直接实施并在验证后合并到 `dev_01`

## 1. 问题与证据

### 1.1 修订表单站内切换后仍不回显

`/workflows`、`/workflows/new` 和 `/workflows/:id/revise` 使用同一个 `WorkflowsView` 组件。现有代码只在 `onMounted` 中加载修订详情；Vue Router 复用组件实例时不会再次执行 `onMounted`，因此从列表页或新建页站内进入修订页时表单为空。直接刷新修订 URL 能回显，所以详情接口和数据库数据本身不是根因。

### 1.2 当前数据库没有 1688 寻源结果

本地数据库中存在 4 个已完成工作流，但 `sourcing_searches`、`sourcing_search_pages`、`sourcing_offers` 和 `sourcing_suppliers` 均没有记录。因此当前页面没有可展示的 1688 商品，不能把“已配置”或“待执行”解释成已查到货源。

项目现有适配器使用本地服务端凭证对 `gw.open.1688.com` 进行了脱敏实测：

- 关键词 `pet hair remover` 返回 574 条、58 页，第一页返回真实商品 ID、标题和 1688 商品链接。
- 使用关键词结果的公开商品图片执行图片上传与图片检索，返回 699 条、69 页。
- 商品详情返回供应商公司、MOQ、SKU、图片和供应商身份信息。

这些结果只证明当前本地凭证和所配置接口在本次测试时可用；运行时仍必须以每次搜索记录的成功、失败和错误码为准，不提供模拟商品降级。

## 2. 目标与边界

本次只完成以下业务闭环：

1. 修订页在直接访问和站内路由切换两种情况下都正确回显。
2. 创建或修订搜客工作流后，依据已保存的产品种子自动创建异步 1688 寻源任务。
3. 关键词和图片两种字段类型严格走各自的参数分支。
4. 寻源页明确展示匹配依据、真实执行状态、错误和分页结果。
5. 继续保持 1688 采购证据与客户联系方式、`contactScore`、客户综合评分隔离。

不新增 OAuth 页面，不修改凭证存储方式，不修改客户发现阶段、客户评分、联系信息或与本需求无关的模块。

## 3. 方案

### 3.1 路由复用下的表单加载

使用一个可响应的页面模式监听器替代只执行一次的挂载逻辑：

- `revise:<workflowId>`：清理上一次修订状态，调用详情接口并回填名称、种子类型、种子值、图片资产元数据、目标市场和 Google 搜索选项。
- `create`：清空可能由上一个修订页遗留的表单数据，恢复默认值。
- `list`：加载工作流列表。

异步详情请求增加序号保护，快速切换不同修订页时只允许最后一次请求写入表单。请求失败继续显示现有的加载错误提示。

### 3.2 创建工作流后自动排队寻源

工作流保存事务提交后调用现有 `SourcingService.runForWorkflow`：

- 该方法只创建数据库搜索记录和第一页任务，不在 HTTP 请求内等待 1688 网络调用。
- Worker 继续负责外部请求、重试、租约、分页持久化和错误归一化。
- 提供方未配置时只跳过寻源，不伪造商品，也不阻断工作流创建。
- 后续启动客户发现时再次调用同一入口，查询指纹会复用已有搜索，避免重复任务。

创建修订工作流使用相同逻辑；紧接着启动客户发现也不会重复创建相同寻源任务。

### 3.3 字段类型与参数映射

关键词工作流：

```text
seedType=keyword
seedValue.trim() -> keyword
当前页 -> beginPage
分页大小 -> pageSize
可选采购价格 -> priceStart / priceEnd
```

图片工作流：

```text
seedType=image
本地上传资产或 seedValue 中的公开图片 URL -> 安全读取与图片校验
图片字节 -> product.image.upload -> imageId
imageId + beginPage + pageSize -> product.search.imageQuery
后续分页复用同一个 imageId
```

工作流名称和目标市场属于当前匹配任务的业务上下文，并在结果页回显。Google 高级搜索选项只用于客户发现，不传给 1688。后端不得根据字符串外观猜测类型，必须使用显式 `seedType` 分支。

### 3.4 寻源页真实状态

接口摘要增加当前工作流输入上下文；前端展示：

- 工作流名称。
- 匹配类型：产品关键词或产品图片。
- 实际查询值。
- 目标市场。

没有搜索记录时显示“待执行”和“开始寻源”；存在搜索后才显示“重新寻源”。成功、失败、部分成功、未配置和分页失败继续使用独立状态。商品卡片只来自持久化的提供方响应，不增加模拟数据。

## 4. 错误处理与性能

- 创建工作流只等待数据库排队，不等待外部网络，避免拉长保存响应。
- 外部超时、限流、权限、Token、图片和响应结构错误继续由 Worker 归一化并按现有规则重试。
- 所有工作流、搜索、分页和商品查询继续显式使用 `ownerUserId + workflowRunId` 隔离。
- 分页只读取请求页，不执行全表扫描。
- 日志、接口和快照不输出 AppSecret、AccessToken、签名或图片 Base64。

## 5. 测试与验收

自动化测试覆盖：

1. 同一组件从新建页切换到修订页后回显全部字段。
2. 从修订页切回新建页后不残留旧值。
3. 创建和修订工作流完成后调用寻源排队入口，未配置时不影响保存结果。
4. 关键词任务持久化关键词参数，图片任务持久化图片 URL 并在执行时只用上传返回的 `imageId`。
5. 寻源页待执行状态显示“开始寻源”，并回显工作流匹配上下文。
6. 现有分页、失败重试、租约、评分隔离和所有前后端回归测试保持通过。

运行态验收：

- 对现有关键词工作流创建真实搜索，等待第一页成功并确认数据库存在真实商品与供应商记录。
- 读取分页摘要，确认总数、总页数和当前页商品数一致。
- 构建前端并检查页面无控制台错误。
