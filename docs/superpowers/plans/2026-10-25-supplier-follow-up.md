# 采购旺旺催办实现计划

> **For agentic workers:** 使用 superpowers:executing-plans，在当前已授权工作区逐项实现；保留已有未提交修改，本次不另行提交或推送。

**Goal:** 已采购待发货履约订单能准确联系其有效采购单供应商。
**Architecture:** BFF按登录账号订单及独立采购资源授权查询订单关联采购明细；只返回已付且尚有待发数量的有效单据。列表催办打开明细弹窗，唯一对象自动尝试打开旺旺，多对象分别选择；打开前重新查询、核验contactVersion。Mock不唤醒虚构账号，真实provider预留查询接口。
**Tech Stack:** Vue 3/TypeScript、NestJS、现有FOP provider、Vitest/Jest。
**Spec:** 用户本轮请求及本文件；需求/字段最终同步到需求9.10与OpenAPI。

## 约束与设计选择
- 催办仅联系，不发送消息、不更新采购流程。订单/客户信息不放入外部聊天URL。
- FOP采购单hzkj_sellers_ww来自实际1688订单sellerLoginId；关联以源单ID/分录ID为准，禁止按SKU默认供应商匹配。已取消/退款/已发货采购不参与。
- 采购岗位+本地数据范围+FOP订单白名单+采购单白名单；接口不接受userId/supplierId/旺旺账号作为选择来源。
- 独立查询供应商信息，不能添加到所有订单列表或图表响应。
- 单订单多供应商逐采购单显示：采购单号、1688单号、供应商、旺旺、待发SKU/数量。缺账号明确提示，不猜测。
- 本地FOP库已确认账号来源及单据关联，尚未找到现成可用的催办HTTP接口；生产跳转协议需与既有FOP部署联调。后端只接受严格白名单旺旺URI，浏览器无法证明客户端打开或消息送达。

## Review Focus
- 越权订单/采购单和跨订单明细：403/404或过滤，不能泄露供应商。
- 重采、部分发货及多供应商：只取当前有效已付款采购及对应待发明细。
- 页面期间账号/供应商变化：contactVersion不一致409，重新选择。
- 恶意跳转、中文账号和协议参数：只允许指定旺旺协议、指定接收人，无任意URL。
- 弹窗关闭、切页、会话重置、请求错误：忽略过时返回，不延迟唤醒。
