# 工作台部门筛选与收款先后顺序

需求：五个岗位工作台支持按业务部门筛选待办，所有待办优先显示最早收款的订单。

## 实施约定

- 复用现有独立的“全部业务数据”权限供销售总监、订单管理、采购、配货、发运、仓库等协同人员使用；不赋予系统管理权限，也不凭工作台岗位自动扩大其他账号的数据范围。具体账号由管理员配置，FOP 白名单仍为权限上限。
- `fulfillment-orders` 增加可选 `departmentId`，只缩小服务端已授权记录范围，匹配订单所属部门及 `departmentPathIds`。返回 `departments: { id, name }[]`，从当前账号可见订单的所属部门生成，独立于队列、搜索及分页，不向员工开放组织管理接口。
- 本项目业务员直接归属业务部门，因此筛选首先提供业务一至四部，兼容自定义部门。无权限的部门参数返回空结果，不回退成全部数据。
- 六个清单（含异常）统一按有效 `paidAt` 升序、同时间按 ID 排序；空或无效收款日期排最后。服务端先授权、再筛选、再排序，最后汇总并分页。
- Dashboard 异常列表复用该顺序；待办摘要时间取最早收款时间。部门选择写入 URL，搜索/翻页保留，切换部门回第一页，切换工作台/待办保留部门。
- 实际 FOP 适配仍待接入。已核对 `hzkj_orders.dym`：销售部门 `hzkj_dept`，源订单收款日期 `hzkj_receipt_date`；业务队列优先级采用订单收款日期，不代替业绩的收款分录时间。
