# 组织成员维护 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline; preserve all existing uncommitted work.

**Goal:** 组织架构统一维护部门、员工与登录账号；账号权限页独立分配权限，导航遵循组织在前、权限在后。

**Architecture:** 延用当前组织目录事务及系统管理员校验。成员支持资料修改、开通和编辑账号、批量导入与软删除。软删除停用关联账号并撤销会话，保留业务外键和历史身份；不能删除自己或系统管理员成员。

**Tech Stack:** Vue、NestJS、TypeORM/PostgreSQL、现有ExcelJS；不新增依赖。

**Spec:** 本轮用户截图及“先建组织、成员，再分配权限”要求；右上部门信息保留，右下成员操作。实施选择：批量导入Excel/UTF-8 CSV，100行上限，预览校验后整批保存；导入仅建员工档案，账号随后开通。成员资料包括姓名、编号、邮箱、职务、手机、部门及岗位档案。

## Global Constraints

- 仅系统管理员操作，所有身份由会话服务端复核；不能用成员编辑改变账号授权。
- 账号编辑包含登录名、员工邮箱同步、可选密码重置和FOP绑定；修改密码撤销旧会话。FOP绑定仍是本地配置，不假设真实权限解析已完成。
- 删除采用归档，不级联删除业务记录；关联账号停用后登录和已有会话均拒绝。本人及系统管理员不可通过成员删除被停用。
- 不批量写入截图中的私人电话或邮箱；模板使用明确的演示占位内容。

## Review Focus

- 跨目录成员ID与部门、已删除成员、重复邮箱／工号／用户名不得成功。
- 批量含一个错误时不部分保存；CSV引号、空行、公式和超过上限给出错误。
- 部门调动只同步默认本人员工身份，不覆盖经理范围或FOP员工映射。
- 模态框关闭／会话切换清除密码和上传预览，失败保留可修正信息。
- 权限页没有新增或账号资料编辑入口；组织页默认选中部门、成员查询、批量选择范围可靠。
