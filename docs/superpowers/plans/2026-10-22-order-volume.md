# 订单量分析与客户排名实施计划

> 使用 executing-plans 在当前工作区实施；用户已明确要求完成开发，保留现有未提交改动。

**Goal:** 将更新后的订单量分析方案接入正式前端，客户保留前十排名与其他合计，并支持单客户搜索趋势。

**Architecture:** 后端在租户、FOP 订单授权及本地用户数据范围过滤后统一聚合，统计与工作台明细共用筛选函数。演示 provider 与真实适配器使用相同订单结构及 HTTP DTO，前端不降级为未授权静态数据。

**Tech Stack:** Vue 3 / ECharts / NestJS / TypeScript。

**Spec:** docs/designs/order-volume/README.md（v1.2 更新以本计划及 API 文档为准）。

## 统一约束

- 综合查询为物流服务商、组织、业务员；客户独立模块默认显示前十客户＋其他。
- 组织营销中心为四部合计；部门展开合计与业务员，汇总使用统一浅紫蓝。
- 时间：月（本年截至当前月）、周（本周及前三周）、日（选定月全部日期，未来为空），时区 Asia/Shanghai。
- 仓库为杭州仓、深圳仓；支持筛选与分仓对比，未分配数据单列，不能丢失。
- 排名按完整查询周期计算并稳定用于各时间点、各仓库；统计排除取消、全额退款，按订单 ID 去重。
- 筛选右上，金额 USD，明细仅在工作台，API 只接受业务条件而不接受权限身份。
