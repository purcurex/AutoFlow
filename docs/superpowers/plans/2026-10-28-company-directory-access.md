# 通讯录账号与协同权限实施计划

> 使用 superpowers:executing-plans 在当前会话逐项执行，使用权限回归测试验证。

**Goal:** 根据用户提供的通讯录建立36名员工及登录账号，并将销售、经理、协同、管理员和无业务权限账号隔离。

**Architecture:** 复用现有组织、账号、FOP数据权限交集。扩展逐图记录范围 `none`，使公司订单查看权限与纯部门分析汇总可以共存。通讯录导入为显式CLI事务，不随部署或启动自动执行；原始人员信息只留本机数据库及忽略目录。

**Tech Stack:** NestJS / TypeORM / PostgreSQL / Vue / ExcelJS。

**Spec:** 用户本次请求及后续确认；业务基线见 [agent.md](../../../agent.md)。

## 已明确的规则

- 邮箱为英文名小写加 @hzdrop.com，初始口令由运行时输入，源码不保存口令。
- Ethan、Robin、Nora、Mason、XinKe 为系统管理员；配置全部工作台及公司业务范围。
- 营销四部员工和外部伙伴为普通销售账号、本人范围；Cici/Dolly/Wendy/Eileen为各自部门经理。
- 商品管理部门及HR暂不开业务数据权限。
- 订单、采购、物流、仓库、信息管理人员可查看全部待办和订单；注册、部门回款、订单分析仅各销售部门汇总，关闭客户/业务员分析及个人业绩和物流财务明细。
- 查看授权不新增FOP审核授权；真实FOP资源和审核仍须独立授权。FOP绑定不从通讯录账号推断。
- 同一公司目录由Ethan账号持有，其他导入账号通过员工关联共享；按用户后续要求，另保留唯一非员工管理员admin@hzdrop.com，通过目录链接共享组织。旧演示账号及其无关员工清理，笔记和文件夹转交新管理员。
- 通讯录主部门用于归属，兼任部门作为资料保留，不据此自动扩权。

## Review Focus

- 英文名大小写重复、缺失和账号冲突必须整批失败，不覆写陌生账号。
- 重复导入不重复建档、不重置已变更密码，保留FOP绑定。
- 汇总账号直接请求客户/业务员/个人分析或明细必须403，订单清单仍可查询。
- 不存在FOP汇总许可时不可用订单记录拼成完整汇总。
- 事务失败全部回滚；实际执行前保存受保护备份，预览不写数据库。
