# 采购退货清单与待出库拦截状态 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 采购及仓库共用实物采购退货清单；待出库单号下展示明确拦截事实。
**Architecture:** 独立只读采购退货网关快照、独立资源白名单，按关联订单分摊行取本地数据范围交集；共享 Vue 清单。拦截为履约单可空独立状态，不推断取消拦截，不改变队列。
**Tech Stack:** Vue 3 / NestJS / TypeScript / ExcelJS。
**Spec:** 用户本轮需求及确认：仅实物退货，两个岗位共用独立退货单清单，展示进度、采购单、供应商、商品数量、退货物流及关联履约单，沿用账号权限。复用现有组件，保留深浅主题。

## Global Constraints
- 不修改 FOP 源码、密钥、真实应用授权或现有待办判定。
- 原有未提交修改保留，不提交 Git。
- 网关状态未知不伪造；HTTP 接口未配置明确失败；演示适配仅开发环境。
- 退货数量只统计授权来源分摊，不泄漏同采购单其它员工来源。仅退款不进入实物退货清单。

## Review Focus
- 两工作台的入口权限各自校验；独立退货、采购及来源订单授权同时生效。
- 跨租户、同单多来源、撤权、缺字段和重复行不能扩大数据。
- 筛选、选中导出与全部导出共用同一范围；超限和失效选择明确失败。
- 登录切换、迟到响应及卸载不残留旧账号数据。
- 缺失拦截事实不显示绿色；完成与其它清单不增加待出库标签。
