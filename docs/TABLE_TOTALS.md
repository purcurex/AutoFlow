# 全局列表合计约定

金额与订单数量列表均以 `TableTotals.vue` 渲染表格底部合计行，统一浅蓝紫色、加粗、数字等宽，支持深色模式。容器滚动时固定在表格底部，横向滚动保持与各列对齐。

- 部门月度回款、业务员月度回款：每列汇总所选年份完整月份，跟随年份、部门及用户权限变化。图表缩放不改变合计。营销中心／部门合计列与明细列分别求和，不能再横向相加。
- 订单量统计、客户前十＋其他排名、各时间桶清单：使用服务端的唯一总计序列；按仓库、月份、周、日列分别显示。未来日期显示“—”，已发生的空数据为 0。
- 履约待办及订单量下钻明细：使用接口 `totals`，基于当前权限和全部筛选结果汇总，分页不改变合计。订单数、商品件数分别标注；多 SKU 订单金额只计一次；不同币种分行展示，默认 USD。空结果保留合计行，数量和金额为 0。请求失败、权限变化或重新加载时清空旧合计。
- 报价：档位数量及单价不可直接累加，合计行明确标注“单价不累加”；方案矩阵的运费、客户运费、组合金额逐列汇总，注明“仅列表统计，各方案独立报价”，不能视作一笔应付金额。尚未完整返回 FOP 报价时显示“待完整报价”，实际零报价显示 0.00。
- 注册会员清单也使用同一合计样式，按已授权汇总序列展示，避免重复计入部门及个人。

金额以显示的两位小数转为整数分再求和，避免小数累加误差。未来新增金额／订单数量列表须复用此组件和统计口径；有分页时 API 必须提供过滤后、分页前的合计，不在浏览器上推测未加载数据。
