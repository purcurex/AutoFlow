01 · 读取链路

FOP 业务单据→同步落库 · 来源事实表→本地展示投影与关联查询→工作台列表

本表用于核对列表需求、本地读取字段与上游业务来源。本表只记录数据展示列，不包含勾选、展开、催办等操作列。列表、筛选、排序、分页及合计读取本地数据库；FOP API 服务于服务端同步落库，不作为页面取数接口。

当前进入工作台或切换清单只读取本地，自动增量已暂停；筛选、翻页、排序与“刷新”只重查本地。“同步数据”由后台任务完成，成功后再重查本地。即时库存查询及审核属于独立按需能力，不纳入本表。

旧 API 已入库展示 · 完整同步待接通

核对状态：本轮新增已采集只读模式：旧 API 完整游标扫描后写入 hz_fop_collected_orders，销售清单直接读取本地已知字段，缺失值留空；下游数据集显示未接入。正式一致快照、变更及授权续验协议仍待 FOP 提供。下方 23 清单矩阵记录完整模式设计；当前实际入库与展示路径以“已采集模式字段”表为准，不能把完整模式映射数量当作本轮已采集字段数量。

配货流程适用版本

现阶段履约审核后自动建配货单；使用备货库存且够用的齐套待审单归“已齐套未审核”。不齐套无法通过 FOP 配货审核，预占／锁库门禁已有；本表现行配货查询仍要求有效配货单。若采集显示已审无单或已审却不齐套，应核查异步任务、关联与版本，不认定正常流程缺口。

未来智能配货改为订单先预占、齐套后建单，需新增订单级待配货视图及五进度、计算结果、预占与变更字段；拦截闭环另待 FOP 补齐。上述未来字段／API 和本地接收适配均待开发，未加入下列现行 348 条映射，不能把本段说明当作已实现。详见扩展需求 V1.4未来智能配货与拦截相关 E13—E15。

三列阅读规则

  • 前端展示字段：按列表列名记录。商品、收件人等同源对象整体描述，不拆成每个属性。
  • 本地数据库字段：先列当前查询实际读取的表和列，并在同格注明来源落库位置。“本地读取已接入”只证明读取路径存在；“仅存储预留”表示列已建但列表尚未返回；“本地映射待补”表示统计或投影不符合确认规则；“仅 Mock 归一化”表示正式模式尚无有效归一化。来源事实写入及展示投影生产仍须接通真实同步。
  • FOP 来源：列业务单据、已核实字段及独立 API 提供状态。API 已提供定义只证明归档契约包含字段；来源确认、真实数据与同步实现分别验收。跨单据已存在本地关联时按来源拆行；未提供的 API 明确标示。
  • 一列多来源：合并左侧单元格，右侧逐行说明各来源。同一单据内的多个值合并在同一行。

商品款数、总数量、金额合计及阶段标签由授权范围内的完整本地数据计算，不要求 FOP 提供同名展示字段。搜索命中一个 SKU，仍返回整笔订单；清单与导出沿用同一权限及数据范围。

来源待确认业务来源、具体源字段或字段含义尚未确认；按同格说明核实。
数据未接入本地字段尚未返回、仅模拟模式提供，或明确缺少该数据；不用于代替全局真实同步状态。

绿色“来源已确认”仅代表对照表业务来源通过核对，不代表真实同步已接通；具体字段或数据仍待补时保留对应警示。两类问题可同时存在。蓝色“本地读取已接入”与绿色“来源已确认”均不代表真实 FOP 同步完成；同步整体状态见上方说明。

API 已提供定义待联调归档接口已定义字段或能力，未证明远端当前部署、完整数据或同步写入已就绪。
API 待确认接口存在，但字段语义、枚举、完整关联或授权契约待 FOP 确认。
API 待提供当前归档未提供所需字段或能力；须由 FOP 新增或扩展。本地计算及组织目录不标此状态。

API 状态独立于绿色来源确认、蓝色本地读取和全局真实同步状态；整行含多项时，仍须阅读同格列出的具体缺项。

采购单 SKU 与数量

按采购单查看时，SKU 数为整张采购单全部有效分录的 SKU 去重种数；数量、已发、未发分别为所有 SKU 的采购、已发货、未发货件数合计。相同 SKU 的多条分录先合并，再汇总整单。例如 SKU A 采购 10 件、已发 6 件，SKU B 采购 5 件、已发 5 件，则显示 2 SKU、采购 15、已发 11、未发 4。

组头统计不随展开分页或某笔关联履约单变化，也不能先排除已发完的 SKU 再统计；保留现有数据权限校验。待创建采购单组尚无采购主单，仍按待采购需求汇总，不显示已发、未发。本地组头已改为采购主单全部未移除分录汇总：SKU 取 hz_fop_source_lines.sku_code，数量取 hz_fop_procurement_line_details.ordered_quantity 与 supplier_shipped_quantity；未发为两者之差。完整来源关系及整单授权必须通过校验，未知、异常数量及取消量不明时阻断。该实现只证明本地读取与计算路径，真实同步尚未接通。

物流信息

未支付展示履约单物流决策的自定义物流渠道。待审核按英文自定义物流渠道名称、中文实际物流渠道名称直接分行展示，不加“自定义”“实际”前缀；Customer 后依次为物流信息、发货仓库。客户运费报价设置默认实际渠道后，同步订单时即可带入，履约审核时确认后续发货渠道，此时尚未获取跟踪号。已审核清单沿用相同列顺序，展示已完成审核操作的履约订单；物流信息追加有效跟踪号，无号显示“尚未获取”。页面与导出采用相同口径。

制作发运单时获取并回写跟踪号；删除发运单清空对应号码，重建后以新号码更新。同步变更须同时撤销旧发运关联与号码事实、清空包裹号码镜像并重算受影响订单；空值必须覆盖旧值。读取时仅接受当前有效关联且未删除的发运单号码，不回退旧包裹镜像。发运工作台以发运单渠道及号码为准，全程 QC、尾程 WC 标记置于号码后；收货通知使用本单国内物流公司名称及运单号，不沿用履约发货渠道与 QC/WC 标记；退货物流尚缺的渠道映射继续保留待补。

金额与时间

履约总额对应 hzkj_total_amount，产品金额对应 hzkj_order_amount；须按现行落库定义写入，避免沿用旧直接查询适配的金额口径。结算币种以 hzkj_settlecurrency 为准，RMA 退款币种以 hzkj_tocurr 为准。

客户向 FOP 付款时间为 hzkj_receipt_date；C 端买家付款时间为 hzkj_datetimefield。本地已分别预留 customer_paid_at、consumer_paid_at，当前列表兼容返回的 consumerPaidAt 仍读取前者，不可依据接口名称认定已展示 C 端时间。备货创建时间为 hzkj_bizdate（创建时间）；客户付款时间待 FOP 通过收款单回写。

采购筛选规则

采购完成口径已确认采购阶段完成＝供应商全部已发货。按履约单查看，要求本单采购需求全部发出；按采购单查看，要求整张采购单全部有效 SKU 已发出、未发数量为 0。部分发货不算完成，无需等待仓库收货或入库；未取得完整发货事实时不推定完成。其余筛选细则仍待逐项核对。

客户已支付且未取消、存在新采购需求的履约单进入采购队列。使用全款备货库存且无需新采购的履约单不进入待采购；供应商全部已发货的订单进入采购完成，不再进入待采购或已采购待发货。

  • 待创建采购单：未创建采购单，或仍有未覆盖采购需求。
  • 待推 1688 采购：已有采购单，平台下单尚未推送或未全部推送。
  • 待支付采购款：已有采购单且不存在待推送动作，采购款未付；旧数据的部分付款仍归此项。
  • 采购退款待跟进：采购付款状态为已退款，且未进入供应商全部已发货阶段；标签优先于推单、付款状态。
  • 供应商待发货／部分发货：采购单已创建、采购款已付、平台下单成功或无需平台下单；供应商未发货／未全部发货。
  • 采购完成：关联采购已覆盖本单需求，供应商全部已发货；不能仅以已下单、已付款判定完成。

履约订单视角的主状态直接取本地原生字段；具体付款、下单、供应商发货标签及进度筛选保留独立事实。待采购与已采购待发货限原生采购状态 0／1／2；采购完成为 4（已发货），后续到 3（已入库）仍保留完成记录。无新采购需求的备货库存订单排除，未知原生状态提示数据未就绪。按采购单查看已采用采购主单有效分录汇总：整单未发数量为 0 且采购量大于 0 才完成；未知或不完整数据明确报错，不因某笔关联履约需求发完而判整单完成。未创建采购单统一成组。来源同步及其余归一化规则后续与 FOP 逐项核对。

RMA 行粒度

同一履约单关联多张售后单时分别占行，各行仅展示当前售后单的退款金额、原因及类型。分页、搜索、勾选与导出均以售后单为单位；原订单金额与商品总量按履约单去重，退款金额不跨售后单汇总。
