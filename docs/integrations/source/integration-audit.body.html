02 · 重要行为与修复

  • WORKBENCH_READ_MODE 仅允许 local；历史 Kingdee 清单查询只保留在未注册的诊断提供器，生产工作台无远端清单回退。独立认证、目录及分析能力仍保留。
  • 快照先持久收齐，按受控清单准备跨页主单／分录身份，再发布完整事实；未验证身份不对外展示，缺关联目标阻止激活。重复调用同一 requestKey 恢复已收页及本地发布进度。
  • 完整快照省略明细时清除旧详情；删除、解除关系、包裹和跟踪号重新选择同步更新，不能保留历史物流值。
  • 授权普通续租保留语义版本与grant身份，避免无变化导出误报冲突；归属变化尚未同步时立即失效。可信旧员工绑定经当前完整目录核验迁移，停用／移除会写入失效绑定以阻断旧字段回退，未验证裸ID不能提升权限。导出使用独立强制续验与最终交付检查。
  • 审核一旦提交后结果不确定，显示待核实，不宣称未提交、不自动重试，并停止批次剩余操作。即时库存按客户＋SKU＋仓；备货库存选单按客户＋SKU跨仓、未选单限本人，全款与押金分别处理。
  • 移除采购退款申请与实物退货的错误映射；真实实物退货接口和实体未提供，返回明确不可用。异常分类及部分库存使用事实仍待正式来源，是否纳入异常清单保持未知；供应商催办仍待专用接口。
  • 总规则新增字段对照表与代码双向同步，代码、API状态、字段说明及证据摘要一并更新。

03 · 字段与 FOP 交接

字段对照表维持“展示字段 → 本地数据库 → FOP来源”三列，包含23张清单、287个展示字段组、348条映射。API已提供定义待联调、待确认、待提供单独标记；本地读取和来源确认都不能替代真实写入验收。

已有接口仍参考19个功能包、27份归档定义，特别采用独立17号原始事实包，修正合并OpenAPI落后导致的误判。hzkj_state 已定义；采购付款／1688字段已定义但版本语义待确认；真实总金额与结算币种、实际物流渠道、部分收货字段和实物退货仍明确待提供。afterOrderId只表示主键续读，不能冒充可靠变更流。

HyperZone智能办公平台项目FOP扩展开发需求列出C01—C11待确认、E01—E12 FOP待开发、B01—B08本项目配套和T01—T19验收，含目标单据、字段级契约、特殊业务逻辑及完整对照清单。服务交接契约与领域JSON Schema是本项目接收格式，仍需FOP确认发布。
