01 · 明确结论

已通过旧 API 完成一次新初始化，449 页、44,855 笔唯一订单、80,188 条商品明细真实写入 PostgreSQL 数据库 autoflow_local_demo。工作台现已读取 hz_fop_collected_orders 的已激活批次，浏览器确认真实订单、商品、客户、仓库与时间可展示；总金额和结算币种缺失显示空值。此前“仅保存原始文件、没有可读订单表”的阻塞已解决。

这是已采集只读模式，完整业务副本 hz_fop_workbench_orders 仍为空，未伪造一致快照或授权租约。六项新同步服务缺失不会再阻止已有数据展示。审核、实时库存和其他独立实时能力仍遵守暂停开关；本轮没有执行审核或库存写操作。

02 · 遗漏诊断

在本轮已采集范围、管理员不加部门／个人／时间／搜索过滤的视角中，未明确整体出库的 31,094 笔订单全部被待支付、待审核或异常待核查清单覆盖，去重后遗漏 0 笔。其中有效未取消 30,574 笔、取消 520 笔；出库状态未知的 52 笔按待核查保留。全部 44,855 笔的 SQL 与独立判定结果一致。

这不等于源端全业务零遗漏：12,615 笔目标订单的历史业务员未映射当前目录，普通员工只看到其当前权限范围；源端未返回数据、权限外数据、未采集实体、采集后变化均无法据此次旧分页证明完整。异常待核查是保留入口，不是已证实流程缺陷。

现行规则继续有效：履约审核后 FOP 自动建配货；备货库存足够即齐套未审，归配货“已齐套未审核”；不齐套不可审核且已有预占锁库。当前缺关联事实不推定无配货单。未来订单先预占、齐套后建单另案开发；订单拦截闭环待 FOP 补齐。

04 · 缺失字段与服务

产品金额已有值并可查看；总金额、结算币种、运费、税费、优惠和下游关联事实尚未提供，暂时留空。2 笔空明细导致总数量未知，不补零。采购、配货、发运、收货通知、备货、RMA、实物退货等数据集尚未采集完成，页面显示“未接入”，不表示 FOP 中没有单据。

租户、公司和旧 API 凭证已经可用，无需重新索取。下面缺项仅用于完整同步协议；旧访问令牌不能未经源端确认就充当新服务授权。
